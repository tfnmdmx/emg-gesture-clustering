# 增量化重构方案 — 单录制 shard + 断点续跑 + 特征缓存

本文档记录把整条流水线从**全量批处理**改造为**单录制原子单元**的设计。**本次重构已全部落地**（见 §7，五步全打勾）；下面的"改造前"动机描述的是重构前的痛点。

改造前的痛点：

- 旧 `segment.py` 把 `seg_rows / clip_rows / rec_rows` 攒到全部跑完才 dump 三张 CSV — 长跑崩了就丢光。
- 旧 overview PNG 渲染耗时占主导，但重跑无 skip 逻辑，已生成的图被无谓重画。
- 旧 `cluster.py` 每次换 k / 换 `--subject-norm` 都在 `groupby("source_file")` 循环里重新加载所有 npz 重算 apex 特征。
- 旧 `export_clips.py` 长跑中断后已生成的 clip npz/png 也会被重写。

核心思路：**让每条录制成为独立、可复用、可断点续跑的原子产物**。现状：`segment.py` 写 per-recording shard + features 缓存并支持 `--workers` 并行，`cluster.py` 经 `features.feature_by_seg()` 命中 `out/features/{stem}.npz` 缓存，`export_clips.py` 按 clip 跳过已存在产物。

> 顶层 `segments.csv / clips.csv / recordings.csv` 的 schema **不变**，下游 cluster.py / export_clips.py 不用动接口。仅新增可选 CLI flag。

---

## 0. 跳过检测契约（贯穿全流水线）

**核心原则**：每个阶段在拿到上层输入（数据路径 / CSV 行）后的第一件事，是用**确定性函数**从输入派生 cache key，去检查对应下游产物是否已存在；存在即 skip，不再做任何重处理。

### 0.1 通用三步

```
上层输入  ──derive(input)──>  cache key  ──check(out_dir, key)──>  exists?
                                                                    ├─ yes → SKIP
                                                                    └─ no  → 处理 + 原子写
```

### 0.2 各阶段契约

| 阶段 | 上层输入 | 派生 key | commit point（存在 = 完成） |
|------|---------|---------|----------------------------|
| **Stage 1** `segment.py` | `path: str` (npz) | `info.stem = parse_file_info(path).stem` | `shards/{stem}/recording.csv` |
| **Stage 2 缓存** `segment.py` 副产物 | 同上 | 同上 | `features/{stem}.npz` |
| **Stage 2 聚类** `cluster.py` | `segments.csv` 行（`source_file`） | `stem = source_file.removesuffix(".npz")` | 不 skip（K/norm 总可能变），但读 `features/{stem}.npz` 命中即免算特征 |
| **Stage 3** `export_clips.py` | `clips.csv` 行（`source_file` + `clip_id`） | `(stem, cid)` → `clips_export/{stem}/c{cid:04d}` | `clips_export/{stem}/c{cid:04d}.npz` **和** `.png` 同时存在 |
| **辅助** `plot_cluster_features.py` | `segments_clustered.csv` 的 `group` | `group` 本身 | `feature_maps/{group}_features.png` |
| **辅助** `build_anim_gallery.py` | `out/segments/{label}/*.npz`（export.py 产物） | `{label}/{stem}` | `hand_anim/{label}/{stem}.html` |
| **辅助** `export.py` | `segments_clustered.csv` 行 + `labels.csv`（per-cluster 标签，默认 `<out>/labels.csv`） | `{label}/{label}__{subject}-{hand}__{stem}__seg{seg_idx}.npz` | 该 npz 存在 |

### 0.3 派生函数纯净性

- key 只由**输入路径**和**CSV 显式列**派生，不依赖任何外部状态（时间戳、随机数、当前 cwd、并发顺序）
- 给同一上层输入两次跑出来 key 必须 bit-identical
- 这保证：手工删某个 shard 目录 → 自动重处理；手工不删 → 永不重处理

### 0.4 commit point 原子性

- 单产物（PNG / npz / html）：写 `<file>.tmp` → `os.replace(<file>.tmp, <file>)`
- 多产物（Stage 1 的 shard 含 4 个文件）：约定**最后一个**写的文件（`recording.csv`）才是 commit point；它存在 = 所有兄弟文件已就位
- 半写入的 `<file>.tmp` 在下次启动时被覆盖，不污染缓存

### 0.5 `--force` 与 `--index-only`

- `--force`：跳过 0.1 的 exists 检查，无条件重处理
- `--index-only`：跳过派生 + 处理，直接走最后的汇总步骤（Stage 1 专有）

## 1. 新输出布局

```
out/
├── shards/                                          ← Stage 1 新增：单录制 atom
│   └── {subject}__{date-hand}__{stem}/              ← key = info.stem，与既有命名对齐
│       ├── overview.png                              # 原 overview/{stem}.png
│       ├── segments.csv                              # 该录制的 burst（0 行也写）
│       ├── clips.csv                                 # 该录制的 clip（0 行也写）
│       └── recording.csv                             # 该录制 1 行 QC = 完成标记
├── features/                                         ← Stage 2 新增：apex 特征缓存
│   └── {subject}__{date-hand}__{stem}.npz           # 字段：seg_idx, feature (n_seg, ja.shape[1]≈20), rest
├── clips_export/                                     ← Stage 3：per-recording 子目录
│   ├── {subject}__{date-hand}__{stem}/              ← 与 shards/ 命名一致
│   │   ├── c0000.npz                                 # 单 clip 切片
│   │   ├── c0000.png                                 # 6-frame 关键帧
│   │   ├── c0001.npz
│   │   └── ...
│   └── index.html                                    # 跨录制总览（增量刷新）
├── segments.csv                                      ← 由 shards/*/segments.csv 自动 concat
├── clips.csv                                         ← 由 shards/*/clips.csv 自动 concat
└── recordings.csv                                    ← 由 shards/*/recording.csv 自动 concat
```

**为什么 shard 命名用 `{subject}__{date-hand}__{stem}` 平铺**：
- 与 `info.stem`（`io_utils.parse_file_info` 的 `FileInfo.stem`）、`features/*` 和 `clips_export/{stem}/*` 全局一致
- `ls shards/` 一眼览全
- glob `shards/*/recording.csv` 一行 concat，不用多层 walk

## 2. Stage 1 — segment.py 改造

### 2.1 单录制处理流程

```
load_npz → emg_seg / pose_seg / 匹配 / QC   (不变)
        ↓
write_shard(shards/{key}/):
        - overview.png       ←  plot_overview_dual 输出
        - segments.csv       ←  该录制 burst 行
        - clips.csv          ←  该录制 clip 行
        - features.npz       ←  apex_pose_feature 缓存（写到 features/{key}.npz）
        - recording.csv      ←  最后一个落盘，标志 shard 完整
        全部走 <file>.tmp → os.replace 原子写
```

**recording.csv 是 commit point**：存在 ⇒ 该录制全部产物都已 ready。下次启动 skip 检查只看它。

### 2.2 启动时的 resume 逻辑

```python
for path, info in work:
    shard_dir = os.path.join(cfg.out_dir, "shards", info.stem)
    commit = os.path.join(shard_dir, "recording.csv")
    if os.path.isfile(commit) and not args.force:
        print(f"SKIP cached: {info.stem}")
        continue
    process_one(path, info, shard_dir)
```

### 2.3 顶层 CSV 汇总

每次 `segment.py` 跑完，扫 `shards/*/{segments,clips,recording}.csv` → pandas concat → 写顶层三张 CSV。下游全部走顶层 CSV，行为零差异。

```python
def rebuild_index(out_dir):
    import pandas as pd, glob
    for name in ("segments", "clips", "recording"):
        rows = []
        for p in sorted(glob.glob(f"{out_dir}/shards/*/{name}.csv")):
            rows.append(pd.read_csv(p))
        df = pd.concat(rows, ignore_index=True) if rows else pd.DataFrame()
        # recording.csv → recordings.csv（单复数差异）
        top_name = "recordings" if name == "recording" else name
        df.to_csv(f"{out_dir}/{top_name}.csv", index=False)
```

### 2.4 新增 CLI（resume / 并行 / 局部重跑相关）

| 参数 | 默认 | 行为 |
|------|------|------|
| `--force` | off | 已有 shard 也重处理 |
| `--no-overview` | off | 跳过 PNG 渲染（CSV-only 加速 ~3-5x） |
| `--index-only` | off | 跳过录制处理，仅 `rebuild_index()` |
| `--workers N` | 1 | `multiprocessing.Pool` 并行；worker = 一条录制 |
| `--subjects a,b,c` | none | 仅处理逗号分隔的 subject 列表（局部重跑） |
| `--only-subject XXX` | none | 单 subject 的别名，向后兼容 |
| `--only-hand left\|right` | none | 仅处理指定手 |

> 注：上表只列与本文档（resume / 缓存 / 并行）直接相关的 flag。`segment.py` 还有一大批检测器参数
> （`--pose-pct/--pose-mad/--min-static-s/--min-motion-s/--move-enter/--move-exit/--enable-r2/--enable-r7/...`），
> 与增量化无关，见 `segment.py --help`。

### 2.5 并行细节

录制处理完全独立（cfg 只读、io_utils 无状态），直接用 `multiprocessing.Pool`：

```python
from multiprocessing import Pool
with Pool(args.workers) as pool:
    for _ in pool.imap_unordered(
        functools.partial(process_one, cfg=cfg, out_dir=cfg.out_dir),
        work):
        pass   # 每个 worker 自己落 shard，主进程不收集行
```

注意：matplotlib 在多进程下要 `matplotlib.use("Agg")`（`export_clips.py` 顶部已示范）。worker 内 import 时再设。

## 3. Stage 2 — cluster.py 特征缓存

### 3.1 改造前的现状

重构前，`cluster.py` 在 KMeans 循环里直接 `groupby("source_file")` 重 load + 重算：

```python
for fname, fdf in gdf.groupby("source_file"):
    _, ja = io_utils.load_npz(...)        # ← 每次重跑都重 load
    for row in fdf:
        feats.append(apex_pose_feature(ja, s, he, rest, fs))   # ← 重算
```

apex 特征是 `(joint_angles, start, hold_end, rest, fs)` 的确定性函数，纯重复劳动。

### 3.2 改造

**Stage 1 顺便写**：segment.py 在 load 完 ja 之后顺便算 apex 特征，写到 `features/{key}.npz`：

```python
# in segment.py process_one（实际为 _atomic_savez 原子落盘）
rest = np.nanmedian(ja, axis=0)            # nan-aware：丢帧不污染 rest
feat_arr = np.stack([
    features.apex_pose_feature(ja, s, he, rest, cfg.fs)
    for (s, _), he in zip(segs, hold_ends)
]).astype(np.float32) if segs else np.empty((0, ja.shape[1]), dtype=np.float32)
_atomic_savez(paths["features"],          # paths["features"] = out/features/{stem}.npz
              seg_idx=np.arange(len(segs), dtype=np.int64),
              feature=feat_arr,
              rest=rest.astype(np.float32))   # rest 也存：跨被试归一化要用
```

**Stage 2 直接读**：cluster.py / evaluate.py / plot_cluster_features.py 全部经共享提取器
`features.feature_by_seg(source_file, fdf, fs, features_dir, input_dir)`，它优先命中
`out/features/{stem}.npz` 缓存，未命中则重 load 并用同样的 nan-aware `rest = np.nanmedian(ja, axis=0)` 现算：

```python
# in cluster.py
for fname, fdf in gdf.groupby("source_file"):
    fdf = fdf.sort_values("start_sample")
    feat_by_seg, hit = features.feature_by_seg(
        fname, fdf, cfg.fs, features_dir, args.input_dir)
    for ridx, row in fdf.iterrows():
        feats.append(feat_by_seg[int(row["seg_idx"])])
        idxs.append(ridx); subs.append(subj)
```

### 3.3 收益

换 k / 切归一化 / 切聚类粒度的重跑时间：分钟级 → 秒级。
KMeans 本身廉价（< 1 s），瓶颈全部是 npz IO + apex 提取，全干掉。

## 4. Stage 3 — export_clips.py 断点续传

### 4.1 改造

`export_clips.py` 的 clip 循环里加 skip。实现的磁盘布局是 per-recording 子目录
`clips_export/{stem}/c{cid:04d}.npz`（由 `_clip_paths()` 解析，与 shards/ 命名一致），**不是**平铺的 `{key}.npz`：

```python
for _, row in rows.iterrows():
    key = _clip_key(info.stem, row["clip_id"])         # 仅用作日志 / npz 内 source_file 元数据
    cpath = _clip_paths(export_dir, info.stem, row["clip_id"])
    npz_out, png_out = cpath["npz"], cpath["png"]      # clips_export/{stem}/c{cid:04d}.{npz,png}
    cached = (not args.force) and os.path.isfile(npz_out) and (
        png_disabled or os.path.isfile(png_out))
    if cached:
        # 仍要把行加进 entries_by_source 以便 index.html 完整
        entries_by_source.setdefault(source_file, []).append({...})
        continue
    ...
```

此外有一层 per-source 短路：先用 `_row_done()` 判断该 source 的所有行是否全部已缓存，全缓存就完全跳过
`load_npz` / `load_skeleton` 甚至不 mkdir 子目录。

### 4.2 CLI

| 参数 | 默认 | 行为 |
|------|------|------|
| `--force` | off | 已有 npz/png 也覆写 |
| `--no-png` | off | 只写 npz，跳过关键帧 PNG |
| `--limit N` | none | 每个 source 最多导出 N 个 clip（pulse.sh 用 `RAW_LIMIT` 透传） |

> export_clips.py **单进程**，没有 `--workers`（早期设计里设想的"每 source 一 worker"并未实现；它只有 `input_dir / --out / --fs / --no-png / --limit / --force`）。并行只在 Stage 1 `segment.py --workers` 上落地。

### 4.3 index.html 流式

把单 source 的 HTML 片段写到 `clips_export/_parts/{source}.html`，最后再 concat。这样跑断也能浏览已渲染部分。或者每个 source 处理完直接重写完整 `index.html`（成本低，更简单）—— **推荐后者**。

## 6. 改造前后对比

### 长跑被打断

| 场景 | 改前 | 改后 |
|------|------|------|
| segment.py 跑 8 小时崩在第 7h | 0 行 CSV 落盘，全部白干 | 已完成的录制 shard 都在；重启自动续跑剩余 |
| export_clips.py 跑 1000 clip 断在 800 | 800 个 npz/png 没有 index 不可用 | 重启从 801 开始，index 已增量更新到 800 |

### 选择性重跑

| 场景 | 改前 | 改后 |
|------|------|------|
| 某条录制阈值不合理想单独重跑 | 没法，只能整体重跑 | `--only-subject XXX --force` |
| 想看 PNG 但 CSV 已有 | 整体重跑 | `--only-subject XXX --force`（不传 `--no-overview` 即渲染 PNG） |
| 换 k 重聚类 | 重跑 segment + cluster ~ 几分钟 | 直接跑 cluster.py，秒回 |

### 并行

| 场景 | 改前 | 改后 |
|------|------|------|
| 100 条录制单机 | 单进程，~30 分钟 | `--workers 8`，~5 分钟 |

## 7. 实施顺序

1. ✅ **Stage 1 shard 落盘 + resume + index 汇总**（最大 ROI）
2. ✅ **Stage 2 特征缓存 + cluster.py 读缓存**（解锁 k 调参速度）
3. ✅ **Stage 1 `--workers` 并行**（每条录制一个 process；pulse.sh 用 `WORKERS=N` 透传）
4. ✅ **Stage 3 export_clips resume + index 流式**
5. ✅ **辅助脚本 skip-existing**

每步独立测试：Stage 1 改完跑一次现有数据，diff `segments.csv / clips.csv / recordings.csv` 内容应与改前完全一致（行序可能差异，sort 后比较）。

## 8. 风险与回滚

| 风险 | 缓解 |
|------|------|
| shard 半写入污染 cache | `<file>.tmp + os.replace` 原子写；commit point = recording.csv 最后写 |
| 老 out 目录无 shards/features，cluster.py 异常 | cluster.py 保留 fallback 路径（无 features 时现算） |
| 并行下 matplotlib 状态污染 | worker 内 `matplotlib.use("Agg")`，每张图独立 fig + plt.close |
| 顶层 CSV 行序变化导致 diff 噪声 | `rebuild_index` 按 (source_file, seg_idx/clip_id) 排序后写 |

回滚：删 `shards/ features/` 两个目录 + 跑一次原版 segment.py（保留旧入口即可）。

## 9. 不在本次改造范围内

- 切换 storage 格式（parquet / arrow）— 当前 csv 足够，IO 不是瓶颈

- 增量加新文件的"watch 模式" — 用 cron + `--workers` 已能覆盖
- cluster.py / export.py 的输出 schema 变更
