## 1. 背景：架构曾处在"换引擎"的半成品状态（已收尾）

> **状态（2026-06-04）**：下表描述的是**改造前**的中间状态。当前主路径已统一到
> `action_segmentation.segment_recording`（pose 迟滞机 + EMG 补切，每动作一段 = 运动 run +
> 其后真实 hold），速度峰切分 `velocity_peak_segments` 已退出线上、仅 diag_seg.py 用作对照；
> 线上聚类是 `cluster.py`（静态 apex 姿态 + KMeans），它消费 `out/features/{stem}.npz` 缓存。
> 下表保留作历史溯源。

当时（改造前）两个核心环节都换了引擎，但旧引擎没拆干净、新引擎有结构缺陷：

| 环节 | 旧引擎 | 当时的新引擎 | 当时状态 | 现状 |
|------|--------|----------------|----------|------|
| 切分单元 | EMG burst / SMC（static→motion→static）clip | **pose-speed 速度峰 segment**（一峰一段，谷底切分） | 速度峰全局生效，旧 EMG 通路无人消费 | 已换成 `segment_recording`（hold-to-hold 每动作一段）；EMG burst 降级为交叉引用/QC |
| 聚类特征 | hold 期 apex 静态姿态向量 | **定长轨迹（trajectory）特征** | `cluster_traj.py` 走轨迹 | 线上回到静态 apex 姿态向量（`cluster.py`）；`cluster_traj.py` 保留为**未接线实验脚本** |

（注：当时引用的原型脚本 `proto_peak_seg.py` / `proto_hold_seg.py` 已**删除**，逻辑已并入
 `emg_label/pose_segmentation.py` 与 `emg_label/action_segmentation.py`。）下游聚类再好也救不回不尊重手势的边界
 ——这正是 S1 改回 hold-to-hold 切分要修的根因。

## 2. 实测证据（out_peak / jm-0503，旧速度峰切分）

> 这些数字采自**改造前**的旧速度峰切分（`out_peak`），是当时定位问题的事实基础。
> S1 重切后段长/段数已变（jm-0503 ~101→~89 段，真实 hold 中位 0.6–1.0s），故下列具体数值仅供溯源。

- **录制结构高度规整**：每条 **119.0s ± 0.03s**，约 101 clip/录制，运动段时长
  `motion_duration_s` 均值 **0.515s、标准差仅 0.136**（最小 0.25 = `min_gesture_s` 地板）。
  → 段长方差这么小，切的是波形不是语义。
- **运动覆盖率 44%、跨 132 条录制 std 仅 0.036**，即 **56% 时间是静止/持姿**。
  → 这是固定节奏的重复手势协议，**数据本身有清晰的持姿间隙**，并非连续手势。
- **clips ÷ bursts = 2.0**（EMG ~49 burst/录制 vs pose ~101 clip/录制）。
  → 速度峰把每个自然手势（一次肌肉激活）切成了约 2 段。
- **EMG-pose lag QC 全军覆没**：`lag_flag` = early 137 / late 2 / **ok 0**；
  `lag_s` 中位 **-0.61s ≈ 半个手势周期(1.18s/2)**，`emg_pose_corr` 中位仅 **0.22**。
  → lag 估计器锁到了准周期信号的反相位，测的是混叠噪声；文档要求"按 lag_flag==ok 筛"
  会丢掉 100% 数据。
- **聚类结构弱**：实测 silhouette ≈ **0.31**（k=17），簇大小 296–1737 均衡，PCA30 解释 93% 方差。
  → 低 silhouette + 均衡分割 = KMeans 在切连续密度团，不是找离散手势；信息没丢，瓶颈在几何与边界。
- ~~**单位标错**：`pose_range` 中位 178、最大 416 → Manus ergonomics 是度不是弧度，但代码/文档/轴标全写 "rad"。~~
  **[已反转 2026-06-04]** `io_utils.load_npz` 在加载时把 Manus 角度从度转成**弧度**，因此
  `pose_speed`、`move_enter/move_exit` 等阈值确实是 **rad / rad-s**，"rad" 标注现在是**正确**的
  （Config 默认 `move_enter=math.radians(60)`、`move_exit=math.radians(25)`、`pose_min_range=math.radians(15)`）。

## 5. 根因与改进方向

### 5.1 根因（多数已在 S1 处理）

> 1、2 已随 S1 落地解决；3 仅对未接线的 `cluster_traj.py` 成立。

1. ~~**切分单元定义错了**~~ [已解决]：速度峰把"一个手势"定义成"一个速度凸包"，对有持姿间隙的数据过切（A1）、对连续手势又欠切。现 `segment_recording` 以"运动 run + 其后真实 hold = 一个动作"定义切分单元，并由 R2 拆超长连续 run，B5 随之缓解。
2. ~~**新旧引擎混栈**~~ [大体处理]：EMG burst 降级为交叉引用/QC，apex 特征缓存现被线上 `cluster.py` 消费（A3 反转）；全局 xcorr lag QC 仍计算但已降级为非门控诊断列（A4 部分）。
3. **聚类几何与对象不匹配** [仅 `cluster_traj.py`]：对时序轨迹用展平 L2（B1）、又把区分性静态构型减掉（B2）。线上 `cluster.py` 聚的是单帧 apex 静态姿态，不存在此问题。

### 5.2 改进方向（已与用户对齐 2026-06-03；切分部分已实现，落地与原案有出入）

> **实现现实标注（2026-06-04）**：切分方向已落地为 `action_segmentation.segment_recording`，但
> 具体做法与下列原案有几处出入：(a) **不是** `static_motion_intervals`，而是 `pose_hysteresis`
> 迟滞机（STATIC↔MOVING + dip-merge + 相对 settle）；(b) **不是** `pad-动作-pad`，而是
> **无人工 pad 的无缝拼接**——一段 = 运动 run + 其后真实 hold，右边界落在下一个 onset；
> (c) 单位**保持弧度**（未改 deg，见 A6 反转）。聚类方向（DTW/构型/per-subject）多为线上
> `cluster.py` 之外的待办或仅实验脚本 `cluster_traj.py` 相关。

**协议事实（用户澄清）**：录制是 `move → hold → move → hold` 的连续序列（伸食指、静止、
伸中指、静止…），**静止(hold)就是天然的手势边界，不存在"回中性"动作**。目标 = 每个**动作**
切成一段（运动 + 其后真实 hold）。"第一版 EMG burst + pose-speed 交叉引用效果就不错"，速度峰谷切才是
过切来源。"动作太快无停顿""长时间静止"属于**异常段**——**先做对基础切割，异常段后处理**。

**切分（已实现）：回到 hold-to-hold 每动作一段，去掉速度峰过切。**
- ~~用 `static_motion_intervals`~~ → 实际用 `pose_hysteresis`（迟滞 + dip-merge）：两次 hold 之间的 motion run = 一个动作；
- 每个动作输出"运动 + 真实 hold"段，**段间无缝拼接**（不再是人工 pad，也不再被速度峰谷底二次切开）；
- **保留 EMG burst + pose 交叉引用**作为投票/QC + Stage-2 特征缓存源；
- apex 改回 `features.apex_index`（**hold 窗内**偏离 rest 最大帧 = 成型姿态），而非峰速度帧；
- ~~速度峰谷切降级为异常长段后处理~~ → 实际由 **R2**（`enable_r2`，默认开）在干净 EMG-rest 间隙拆超长 run；R7 背靠背否决默认**关**（`enable_r7=False`，常规数据会过切）。

**聚类（多为待办 / 仅实验脚本）：匹配时序几何 + 保留构型 + 跨被试防护。**
- 用 **DTW / soft-DTW**（或时序自编码器嵌入）替代展平 L2 —— **未做**；仅与实验脚本 `cluster_traj.py` 相关，线上 `cluster.py` 聚静态 apex 姿态；
- `repr` 默认保留绝对构型 —— 线上 `cluster.py` **本就用绝对 apex 姿态**；
- 跨被试 **per-subject 归一化** —— **已提供**（`cluster.py --subject-norm center/zscore` → `features.apply_subject_norm`），默认 `none`；
- k 选择稳定性校验 —— 线上 `clustering.select_k_and_cluster`（固定 `--k` 被夹到 n-1 时告警）。

**异常段处理（部分实现）：**
- **长时间静止**：绝对幅度门限 `pose_min_range`（`seg_range_ok`）drop 幻影段——**已有**；超长 hold 标 `review_flag=long_static`（`max_hold_s`）；
- **动作太快无停顿**：连续 run → 超长 motion 段标 `review_flag=long`，并由 R2 段内拆分——**已有**；
- lag QC 已降级为非门控诊断列（全局 xcorr 仍计算、仍多报 early，"移除全局 xcorr"未做）；`static_out_*` 已正名为真实 hold（`hold_*` 别名）；
- ~~单位统一改 deg~~ → **未改**：单位保持弧度（加载时度→弧度），"rad" 标注正确。
