## 1. 背景：架构正处在"换引擎"的半成品状态

当前分支把两个核心环节都换了引擎，但旧引擎没拆干净、新引擎有结构缺陷：

| 环节 | 旧引擎 | 新引擎（当前） | 状态 |
|------|--------|----------------|------|
| 切分单元 | EMG burst / SMC（static→motion→static）clip | **pose-speed 速度峰 segment**（一峰一段，谷底切分） | 新引擎全局生效，旧 EMG 通路仍全量计算但无人消费 |
| 聚类特征 | hold 期 apex 静态姿态向量 | **定长轨迹（trajectory）特征** | `cluster_traj.py` 走轨迹，旧 `cluster.py` 仍被 segment.py 喂数据 |

**一句话核心矛盾**：速度峰切分本是为修复"连续手势被并成 27s 巨段"这个**边缘场景**而生的
（见 [proto_peak_seg.py](../proto_peak_seg.py) 头注），但被全局套用后，在**有清晰持姿间隙**
的常规数据上反而把每个自然手势过切成约 2 段。下游聚类再好也救不回不尊重手势的边界。

## 2. 实测证据（out_peak / jm-0503）

这些数字是后续判断的事实基础：

- **录制结构高度规整**：每条 **119.0s ± 0.03s**，约 101 clip/录制，运动段时长
  `motion_duration_s` 均值 **0.515s、标准差仅 0.136**（最小 0.25 = `min_gesture_s` 地板）。
  → 段长方差这么小，切的是波形不是语义。
- **运动覆盖率 44%、跨 132 条录制 std 仅 0.036**，即 **56% 时间是静止/持姿**。
  → 这是固定节奏的重复手势协议，**数据本身有清晰的持姿间隙**，并非连续手势。
- **clips ÷ bursts = 2.0**（EMG ~49 burst/录制 vs pose ~101 clip/录制）。
  → 速度峰把每个自然手势（一次肌肉激活）切成了约 2 段。
- **EMG-pose lag QC 全军覆没**：`lag_flag` = early 137 / late 2 / **ok 0**；
  `lag_s` 中位 **-0.61s ≈ 半个手势周期(1.18s/2)**，`emg_pose_corr` 中位仅 **0.22**。
  → lag 估计器锁到了准周期信号的反相位，测的是混叠噪声；文档要求"按 lag_flag==ok 筛"
  会丢掉 100% 数据。
- **聚类结构弱**：实测 silhouette ≈ **0.31**（k=17），簇大小 296–1737 均衡，PCA30 解释 93% 方差。
  → 低 silhouette + 均衡分割 = KMeans 在切连续密度团，不是找离散手势；信息没丢，瓶颈在几何与边界。
- **单位标错**：`pose_range` 中位 178、最大 416 → Manus ergonomics 是**度**不是弧度，
  但代码/文档/轴标全写 "rad"。

## 5. 根因与改进方向

### 5.1 根因
1. **切分单元定义错了**：速度峰把"一个手势"定义成"一个速度凸包"。对有持姿间隙的数据过切（A1），
   对连续手势又会欠切——它没有"完整手势"的概念。聚类只是忠实反映了这个错误（B5）。
2. **新旧引擎混栈**：EMG 旧通路、apex 特征缓存、lag QC 既没拆干净、又一直亮红灯（A3/A4）。
3. **聚类几何与对象不匹配**：对时序轨迹用展平 L2（B1），又把区分性的静态构型减掉（B2）。

### 5.2 改进方向（已与用户对齐 2026-06-03）

**协议事实（用户澄清）**：录制是 `move → hold → move → hold` 的连续序列（伸食指、静止、
伸中指、静止…），**静止(hold)就是天然的手势边界，不存在"回中性"动作**。目标 = 每个**动作**
切成一段 `pad-动作-pad`。"第一版 EMG burst + pose-speed 交叉引用效果就不错"，速度峰谷切才是
过切来源。"动作太快无停顿""长时间静止"属于**异常段**——**先做对基础切割，异常段后处理**。

**切分（修正方向）：回到 hold-to-hold 每动作一段，去掉速度峰过切。**
- 用 pose-speed 的 static/motion 区间（`static_motion_intervals`）：两次 hold 之间的 motion run = 一个动作；
- 每个动作输出 `pad-动作-pad` clip（一动作一段，不再被速度峰谷底二次切开）；
- **保留 EMG burst + pose 交叉引用**作为投票/QC（第一版就这么做、效果好）；
- apex 改回"段内偏离 rest 最大帧"（成型姿态），而非峰速度帧；
- 速度峰谷切 `velocity_peak_segments` 降级为**异常长段**的后处理候选，不在基础路径用。

**聚类：匹配时序几何 + 保留构型 + 跨被试防护。**（基础切割对了之后再做）
- 用 **DTW / soft-DTW**（或时序自编码器嵌入）替代展平 L2；
- `repr` 默认**保留绝对构型**（至少提供 raw，或 raw+velocity 拼接），别默认 centered；
- 跨被试前补回 **per-subject 归一化**；
- k 选择加**多 seed 稳定性**校验，落实"宁大勿小"。

**异常段处理（基础切割之后）：**
- **长时间静止**：rec/seg 绝对幅度门限（`pose_min_range`，已有）drop 幻影段；
- **动作太快无停顿**：连续 run 收不到 hold → 一个超长 motion 段，先 `review_flag=long` 标记，
  再决定段内速度峰谷切或丢弃；
- lag QC 降级为非门控诊断列（修对齐方向或仅记录）；伪造的 static_in/out 字段正名；
- 单位统一改 deg 并修正文档/轴标。

## 6. 分步路线图（一步步解决）

按"先校准事实 → 修切分（上游）→ 修聚类（下游）→ 清理"的顺序。每步有明确产出与验收口径。
**先做诊断步（S0），用真图确认方向后再动手改算法。**

- [x] **S0 诊断对照**（低风险、先做）✅ 2026-06-03
      [diag_seg.py](../diag_seg.py)：并排画 EMG burst / 速度峰段 / hold-to-hold 段 + 量化过切。
      **结论（混合方案验证通过）**：
      - 常规数据 jm-0503：vpeak/hold=1.16，55% 的 EMG burst 被速度峰切成 2 段，
        87% 的 hold-to-hold 段只对应 1 个速度峰 → **速度峰在有持姿的数据上过切（A1 成立）**；
      - 连续数据 hzy-1217：一个 hold-to-hold 段含 31 个速度峰 → **hold-to-hold 切不开连续手势**；
      - → 两者互补，确定主方向 = **hold 边界优先、连续 run 内退速度峰谷切**。
      图：`out_diag_s0/*.png`。

- [x] **S1 重做切分单元（基础切割准确性）** ✅ 2026-06-03
      [segment.py](../segment.py) pose 通路从 `velocity_peak_segments` 改为
      `static_motion_intervals` 的 motion run → `pad-动作-pad`；apex 改用
      `features.apex_index`（段内偏离 rest 最大帧）；保留 EMG burst 交叉引用。
      **验收通过**：jm-0503 101→**87 段**（=hold-to-hold 数）、段长 std 0.14→**0.25**、
      apex 100% 落在动作窗内；hzy-1217 55→**15 段**，27.4s 连续段被 **long** 标记（A7 修复）；
      74 测试全过，overview 正常。

- [ ] **S2 异常段处理**：长时间静止（绝对幅度门限）、动作太快无停顿（long 段段内谷切或丢弃）；
      lag QC 降级为非门控诊断列。
      *验收*：异常录制不再产出误导性段；recordings.csv 无"永远报坏"的门控列。

- [ ] **S3 修聚类特征几何**：引入 DTW/soft-DTW（或时序嵌入），`repr` 保留构型，
      补 per-subject 归一化，k 加稳定性校验。
      *验收*：silhouette 明显上升 + 簇库 medoid 人眼可辨为不同手势。

- [ ] **S4 单位与文档收尾**：deg/rad 正名，更新 METHOD.md 与本文 §6 进度。

- [ ] **S5 跨被试验证**：在多被试数据上跑 S1–S3，复核 memory 记录的 subject-contamination 是否缓解。
