# 数据组织重构方案 — 切分 / 打标 / 聚类 / 评估的存储布局

> 状态:**已实现 (2026-06)**。下文原是设计草案;现在 `compact` 分支已按本方案落地,
> 文档同步改为描述**已建成的状态**。核心:把切分/打标/聚类/评估的存储理顺,
> 让"切分 → 打标 → 聚类 → 用标签评估聚类"这条主线顺滑、可删、可对照、可复现。
> 本文逐条回应 7 个已提出的问题,再给出(已落地的)目标布局与分步路线。
>
> **落地结论(几处草案里的开放点,实现时定了):**
> ① 索引存储 = **单文件 SQLite `OUT/index.db`**(权威索引;表
>   `recordings / bursts / clips / annotations / cluster_runs / cluster_assignments / tombstones`),
>   实现于 [`emg_label/store.py`](../emg_label/store.py)。`OUT/shards/{stem}/` 仍是切分**真值**,
>   `index.db` 可随时由 `store.build_index` 从 shard 重建。
> ② 标签真值 = `index.db` 的 **`annotations` 表**(带 `scope`+`kind` 与稳定锚
>   `clip_start_sample/clip_end_sample/seg_version`),**没有 `clip_labels.csv`**;
>   `invalid_recordings.csv` 并入此表(`scope='recording', kind='invalid'`)。
> ③ 聚类/打标/评估的唯一单元 = **clip `(source_file, clip_id)`**;**apex**(`cluster.py`)与
>   **trajectory**(`cluster_traj.py`)两条通道并存,都写 `OUT/cluster_runs/{run_id}/`
>   (`params.json` + `clusters.csv` + `metrics.json` + `gallery/`)并登记进 db。
> ④ 导出走 `OUT/gestures/<label>/`(不再是 `segments/`)。
> ⑤ `segments.csv` → `bursts.csv`。
> ⑥ 永久删除原语 `drop_recording` + tombstone 已实现(webapp 有"删除录制"按钮)。
> ⑦ 重切分后的 `store.remap_annotations` 已实现。
>
> **代码基准:`compact` 分支**。下述读写路径均已对照核对:`emg_label/store.py`、`segment.py`、
> `cluster.py`、`cluster_traj.py`、`evaluate.py`、`export.py`、`label_server.py`、
> `plot_cluster_features.py`、`build_anim_gallery.py`、`pulse.sh`。**单一流程、单一输出目录**:
> `segment` 自动识别数据形态(processed 扁平 npz / raw `{subject}/{date-hand}/{stamp}.npz` 树递归扫描 /
> 或一份 `sample_meta.csv`),所以只有一个 `segment` 命令和一个输出目录 `OUT`(默认 `out`);
> 选被试用 `SUBJECTS=id1,id2`(归一化 `fgw-0917 == fgw0917`)。

## 0. 数据模型(真值/派生关系 — 已实现)

理解一切的前提:**哪些是真值(source of truth),哪些是派生物(可随时重建)。**

```
真值 (truth)                          派生 (derived, 可删可重建)
─────────────────────────────        ──────────────────────────────
shards/{stem}/   ← 切分真值           index.db 的 recordings/bursts/clips 三表
  ├─ recording.csv (1行=完成标记)        ← store.build_index 从 shards/*/ 重建
  ├─ bursts.csv    (EMG burst)         recordings.csv / bursts.csv / clips.csv
  ├─ clips.csv     (pose 动作段)          ← store.export_csv 从 db dump 的便利 CSV
  └─ overview.png                       cluster_runs/{run_id}/  ← 一次聚类的结果
index.db 的 annotations 表 ← 标签真值    gestures/<label>/*.npz  ← export: 已标注 clip
  (scope+kind, 带稳定锚)                 labeled_overview/*.png  ← 同上
index.db 的 tombstones 表 ← 永久删除记录  features/ , traj_features/  ← 特征缓存
                                        cache/**               ← webapp 渲染缓存
```

- **索引/聚类结果不再是顶层大 CSV**,统一进 `OUT/index.db`(SQLite,`store.py` 维护)。
  shards 仍是切分真值;`recordings/bursts/clips` 三表由 `store.build_index` 从
  `shards/*/{recording,bursts,clips}.csv` 重建(每条录制先 `DELETE WHERE source_file=?`
  再插,重切分后留更少 clip 不会留下陈行)。`segment.py` 跑完顺带 `store.export_csv`
  导出顶层便利 CSV `recordings.csv / bursts.csv / clips.csv`(bursts/clips dump 时
  从 recordings JOIN 回 `source_path`),仅供读扁平文件的 dev 工具
  (`diag_seg.py` / `cluster_traj.py` / `visualize_segment.py`)。
- **打标真值** = `annotations` 表,主键 `(source_file, clip_id, scope, kind)`。
  `label_server.py` 每次打标 `set_annotation` upsert 一行(`store.set_annotation`)。
- `clips.csv` 里没有 `gesture_label` 列了(草案里那个"永远是空"的列已删);
  标签全在 `annotations`,需要"已标注视图"时用 `store.labeled_view`
  (`clips LEFT JOIN` 标签注解,随查随新,无快照过期问题)。
- 失效统一进 `annotations`(`kind='invalid'`):clip 级 `scope='clip'`,录音级
  `scope='recording'`;独立的 `invalid_recordings.csv` 已删。
- 永久删除写 `tombstones` 表 + 删 shard;`store.build_index` / `segment.py` 跳过被
  tombstone 的 `source_file`,重切分不会复活。
- `label_server.py` 启动时打开一个共享连接(`store.connect`,WAL),按需查 db,
  不再把整张大 CSV 读进内存。
- QC 列(lag_flag / pose_nan_frac 等)仍留在 `recordings` 表里供随手查询;
  原先那个按全局互相关 lag 阈值筛出的 `recordings_keep.csv` 子集(及 `raw-qc` 子命令)已删。

> 一句话:`shards/` 和 `index.db` 的 `annotations`(+`tombstones`)是真值,
> **其余皆派生,可一键重建**。

## 1. 七个问题:旧现状 → 根因 → 方案(已实现)

### 问题 1 · 网页从顶层 clips.csv 读数据,删除数据操作复杂

**旧现状**:webapp 读顶层 `clips.csv`(派生物)。想删某些数据时:
- 直接删 `clips.csv` 的行 → 下次 `rebuild_index` 又从 shard concat 回来,**删除不持久**;
- 真要删得去删 `shards/{stem}/` 整个目录 + 重建索引,webapp 还得重启重读大表;
- webapp 本身**没有删除原语**,只有 soft `invalid` 标记(语义是"排除",不是"删除")。

**根因**:① 删除目标搞错了——应删真值(shard),不是派生物(clips.csv);② "永久删除"和"软排除"两个概念被混在一个 `invalid` 上;③ 索引是一坨大 CSV,不支持按行增删。

**已实现**:两类操作各有归属:
- **软排除(可恢复)**:打标动作,写进 `annotations` 表(`kind='invalid'`,见问题 2),
  不动 shard。下游查询默认过滤(`store.excluded_recordings` / `store.labeled_view`)。
- **永久删除(不可恢复)**:以录音为单位的一等操作
  [`store.drop_recording(out_dir, source_file)`](../emg_label/store.py) ——
  从 `recordings/bursts/clips/annotations/cluster_assignments` 删对应行 +
  写一条 `tombstones` 记录,防止重切分复活。
  webapp 侧 `LabelStore.drop_recording(stem)` 再额外 `shutil.rmtree` 掉
  `shards/{stem}/` 与特征缓存,并清理内存状态。
- webapp 暴露 **"删除录制"按钮 → `POST /api/drop_recording`**(`label_server.py`
  路由,见 [label_server.py:948-963](../label_server.py#L948)),而不是去编辑 CSV。
- 删除以**录音为最小粒度**;clip 级别只做软排除(单 clip 永久删除没意义,重切分会重新产生)。
  软 `invalid`(录音或 clip)与 `drop` 是两个**不同**的概念,各自独立保留。

### 问题 2 · 标注失效的数据另存一个 CSV,是否冗余?

**旧现状**:失效信息散在三处 —— 逐 clip 标签文件的 `invalid` 列、`invalid_recordings.csv`(录音级独立文件)、export 时直接把失效行剔掉的物化结果。

**判断**:**部分冗余,且割裂。** `invalid` 本质就是一种标注(取值为"废"),没必要单独开一个顶层小文件;录音级和 clip 级是两个 scope,但不该是两套机制两个文件。

**已实现 —— 统一成一张 `annotations` 表,带 scope + kind**(`store.ANNOT_COLS`,主键
`(source_file, clip_id, scope, kind)`):

| 字段 | 说明 |
|---|---|
| `source_file` | 录音 |
| `clip_id` | scope=clip 时为 clip id;scope=recording 时存 **-1** |
| `scope` | `clip` / `recording` |
| `kind` | `label`(手势标签) / `invalid`(失效/废弃) |
| `value` | gesture 名(kind=label 时) |
| `clip_start_sample` `clip_end_sample` `seg_version` | 重切分稳定锚(见第 2 节) |
| `labeler` `labeled_at` `note` | 元信息 |

- `invalid_recordings.csv` 已并入此表(`scope='recording', kind='invalid'`,`clip_id=-1`),
  独立文件**已删**;`label_server.py` 的 `set_recording_invalid` 直接写这里。
- 同一 clip 上 `label` 与 `invalid` 是互斥的 kind(打标时先 `delete_annotation`
  两个 kind 再写其一,见 [label_server.py:352-362](../label_server.py#L352))。
- 没有 `clips_labeled.csv` 物化文件了;"已标注视图"改由 `store.labeled_view`
  随查随新(见问题 5)。
- 好处:一处真值、一套主键、一套加载逻辑;问题 1 的"软排除"直接落这里。

### 问题 3 · 顶层文件每次从子文件夹合并,其实并不必要?

**旧现状**:`rebuild_index()` 每次全量 `glob shards/*/{clips,segments,recording}.csv` → concat → 覆盖三张顶层 CSV。

**判断**:**"有一个索引"是必要的**(webapp/聚类要一张可查的全量表,临时打开几千个小 CSV 更慢);**但"每次全量重 merge 成大 CSV"不必要**。

**已实现 —— 选了 B:单文件数据库 SQLite `OUT/index.db`**(`emg_label/store.py`)。
把 recordings / bursts / clips / annotations / cluster_runs / cluster_assignments /
tombstones 作为表存进一个 `index.db`:

- 删除 = `DELETE WHERE source_file=?` + tombstone(`store.drop_recording`,解问题 1);
- 打标 = `INSERT OR REPLACE`(`store.set_annotation`,标注就是一张表,解问题 2);
- 查看/对照 = 一条 `JOIN`(`store.labeled_view`,解问题 5);
- 评估 = `cluster_assignments JOIN annotations`(`store.clusters_with_labels`,解问题 7);
- webapp 不必把大表读进内存,共享一个 WAL 连接按需查询。
- **重建仍是从 shards**:`segment.py` 跑完(或 `./pulse.sh db` / `--index-only`)调
  `store.build_index`,逐 shard `DELETE` 再插,只更新有 `recording.csv` 提交标记的录制,
  跳过 tombstone。shards/ 仍是真值;`index.db` 是**可从 shards 重建的派生物**。

> 实现说明:`rebuild_index()`([segment.py:307](../segment.py#L307))= `store.build_index`
> +`store.export_csv`。顶层 `recordings/bursts/clips.csv` 降级为**便利 dump**(给读扁平文件的
> dev 工具),不再是索引本体。**不变的原则**:索引永远是派生物,真值在 `shards/` + `annotations`。

### 问题 4 · burst 文件命名为 segment,不合理

**旧现状**:`segments.csv` 存的其实是 **EMG burst**。但 "segment" 这个词同时被用来泛指"要聚类的连续动作段",**一词多义,极易混淆**。

**已实现 —— 改名,术语收敛:**

| 旧名 | 新名 | 含义 |
|---|---|---|
| `segments.csv` | `bursts.csv` | EMG 激活段,辅助/对齐用 |
| `clips.csv` | `clips.csv`(不变) | **pose 连续动作段 = 聚类/打标/评估单元** |

- shard 内文件现在是 `shards/{stem}/{recording.csv, bursts.csv, clips.csv, overview.png}`;
  字段定义集中在 `store.BURST_COLS / CLIP_COLS / REC_COLS`,`segment.py` 的
  `BURST_FIELDS / CLIP_FIELDS / REC_FIELDS` 直接引用它们。
- burst 行主键从 `seg_idx` 改为 **`burst_idx`**;字段
  `source_file, burst_idx, group, start_sample, end_sample, hold_end_sample,
  apex_sample, duration_s, emg_rms, envelope_peak, pose_range, matched_clip_id`。
- clips 字段同步收敛:`clip_start_sample/clip_end_sample` → **`start_sample/end_sample`**;
  `matched_emg_seg_idx` → **`matched_burst_idx`**;`static_in_*/static_out_*` 列**已删**
  (hold 用 `hold_start_sample/hold_end_sample`);那个空的 `gesture_label` 列**已删**
  (标签在 `annotations`);新增 **`seg_version`**(clips 与 recordings 都加)。
- 读它的 `cluster.py` / `cluster_traj.py` / `evaluate.py` / `export.py` 已全部改为通过
  `store.labeled_view` / `store.clips_for_recording` 走 db(见问题 6/7)。
- 术语统一后,文档/代码里 "clip" 指"连续动作段",EMG 的叫 "burst",不再打架。

### 问题 5 · 打标结果不易查看 / 与原数据对照

**旧现状**:逐 clip 标签文件只有 `(source_file, clip_id, gesture_label, ...)`,**看不出这条 clip 是什么**(时长、动作区间、指标全在 `clips.csv`)。要对照得手动 join;物化快照只在手动 export 时更新、会过期。

**已实现:**
- **总是新鲜的标注视图**:`store.labeled_view(conn)` = `clips LEFT JOIN annotations`
  (`scope='clip', kind='label'`),返回每 clip 一行、`gesture_label` 从 `annotations`
  现填,并已默认剔除失效录音(`excluded_recordings`)和失效 clip。随查随新,
  **无物化快照、无过期问题**。`cluster.py / cluster_traj.py / export.py` 都用它取 clip 集。
- **一键对照原数据**:webapp 仍按 clip 渲染 overview/3D 手部回放,点标签即可看动作。
- **稳定 clip 锚点(见下方"跨问题设计")**:标注绑定 clip 采样区间
  (`clip_start_sample/clip_end_sample` + `seg_version`)而非易变的 `clip_id`,重切分后"对照"不会错位。

### 问题 6 · 聚类单元 = clip;apex / 时序两条通道;结果位置要合理

**聚类单元 = clip `(source_file, clip_id)`**(与打标、评估同键)。`bursts` 仅作对齐辅助。

**已实现 —— 两条并存的一等通道,都以 clip 为单元、写同一套合约:**
- **apex 通道(`cluster.py`)**:对每个 clip 在其 hold 内的**静态成形姿态**特征
  (`features.clip_apex_feature`,缓存在 `OUT/features/{stem}.npz`)做 KMeans。
  早期实验 apex 静态曾胜出,所以它是默认/主通道。
- **trajectory 时序通道(`cluster_traj.py`)**:对 clip 的 motion 区间重采样到定长 L
  的**关节角轨迹**(`--repr centered|velocity|raw`)→ z-score → PCA → MiniBatchKMeans;
  特征缓存 `OUT/traj_features/{stem}.{repr}_L{L}.npz`(key 含 repr/L,换算法不重算)。
  作为**一等通道保留并持续深做**。

两通道都通过 `store.save_run` 落同一套产物 + 登记 db:

```
OUT/cluster_runs/{run_id}/              run_id = '{YYYYMMDD-HHMMSS}__{paramhash8}'
  ├─ params.json        # {run_id, channel, created_at, params{unit,channel,k,...}}
  ├─ clusters.csv       # source_file, clip_id, cluster_id  (与 clip 同主键)
  ├─ metrics.json       # evaluate.py 写(见问题 7)
  └─ gallery/           # 每簇 medoid 关键帧 / 3D 手部(apex: *_hands.png;traj: index.html)
```

同时登记进 `index.db`:`cluster_runs(run_id, created_at, channel, params_json)` +
`cluster_assignments(run_id, source_file, clip_id, cluster_id)`。

- 一个 run = 一个目录 + db 登记,**参数自描述**(`run_id` = 时间戳__参数哈希8位,既可读又可复现)。
- `clusters.csv` / `cluster_assignments` 主键与 clip 一致 → 评估时直接
  `cluster_assignments JOIN annotations`(`store.clusters_with_labels`)。

### 问题 7 · evaluate / export 重写为标签驱动(已实现)

**`evaluate.py`(已重写为标签驱动,逐 run)**:`./pulse.sh eval`(`RUN=` 或默认最新 run)。
`store.clusters_with_labels`(`cluster_assignments JOIN` clip 标签 `annotations`)→
[A] 标签驱动 ARI / NMI / purity(标注子集上)、[B] 被试污染(逐簇主导被试占比)、

旧的"先聚类再给簇命名、导出到 `OUT/segments/<label>/"`、以及那个 `(group, cluster_id, label)`
逐簇 `labels.csv` 流程**已废弃**:簇现在活在 `cluster_runs/` 里、用标签评估,而不是命名后导出。

## 2. 跨问题的核心设计:稳定 clip 锚点(已实现)

问题 1/5/6/7 都踩到同一个隐患:**标注主键 `clip_id` 是切分器在录音内分配的顺序号,不随重切分稳定。**
项目正处于"换切分引擎"阶段(切分规则仍在调,见 [docs/切分聚类问题与改进方向.md](切分聚类问题与改进方向.md)),
**每改一次切分,`clip_id=3` 可能指向不同动作,旧标签还引用旧号 → 标签静默错位。**

**已实现:`annotations` 表的每行除 `(source_file, clip_id)` 外带稳定锚:**
- `clip_start_sample, clip_end_sample`(打标当时的区间)
- `seg_version`(切分相关 Config 参数的哈希,由 `segment._seg_version` 计算,写进
  clips/recordings 与每条 annotation)

重切分后跑 `store.remap_annotations(conn, current_seg_version, min_overlap=0.5)`:
对 `seg_version` 过期的 clip 标注,用采样区间最大重叠(IoU 风格)映射到新 clip;
重叠 ≥ 阈值则迁到新 `clip_id` 并刷新锚,**重叠不足 / 无新 clip 则保留并 `note='待复核'`,绝不静默丢弃**。
返回 `{remapped, flagged, unchanged}` 计数。

## 3. 落地布局(汇总)

```
OUT/                                # 唯一输出目录(默认 out);segment 自动识别数据形态,选被试用 SUBJECTS=
├── shards/{stem}/                 ← 真值: 切分原子
│     └─ recording.csv  bursts.csv  clips.csv  overview.png   (segments→bursts 已改名)
├── index.db                       ← 权威索引(SQLite, store.py 维护):
│     表 recordings / bursts / clips        ← 派生, 从 shards 重建
│        annotations                        ← 真值: 统一标注/失效, scope+kind, 带稳定锚
│        cluster_runs / cluster_assignments ← 聚类 run 登记
│        tombstones                         ← 永久删除记录
├── recordings.csv  bursts.csv  clips.csv   ← 派生: db dump 的便利 CSV(扁平文件 dev 工具)
├── cluster_runs/{run_id}/         ← 聚类结果(apex/trajectory 两通道共用):
│     └─ params.json  clusters.csv  metrics.json  gallery/
├── features/{stem}.npz            ← 派生缓存: 每 clip apex 姿态特征(cluster.py/evaluate.py)
├── traj_features/{stem}.{repr}_L{L}.npz  ← 派生缓存: 时序轨迹(cluster_traj.py)
├── gestures/{label}/*.npz         ← export 产物: 已标注 clip 按手势分组
├── labeled_overview/{stem}.png    ← export 产物: 逐录制标注概览
├── hand_anim/{label}/*.html + index.html  ← build_anim_gallery: 每手势动画画廊
└── cache/**                       ← 派生: webapp 渲染缓存
# 已删除: 顶层 segments.csv / segments_clustered.csv / labels_template.csv
```
