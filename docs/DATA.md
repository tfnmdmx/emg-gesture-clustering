# 数据说明 — processed_data 数据盘点（按被试 / 左右手）

本文档说明 `/data/cl_data/ai-infra/processed_data` 下的数据如何被盘点、左右手是怎么解析出来的，并给出按被试 × 左右手的汇总表与使用注意。
对应产物：[../data_inventory.csv](../data_inventory.csv)（每文件一行）、[../data_summary.csv](../data_summary.csv)（被试 × 手别汇总）。

---

## 1. 左右手是按文件名解析的，**不是按文件夹名**

**手别（left/right）和被试都优先从文件名解析**，文件夹名只在文件名无法解析时用作被试的兜底来源（此时手别记为 `UNKNOWN`）。

### 1.1 文件名约定（可解析）

```
{subject}__{date}-{hand}[-{run}]__{timestamp}.npz
例: fgw-0917__20260502-left__20260502_115218.npz
    fgw-0917__20260502-left-3__20260502_104240.npz   (带 run 后缀)
```

解析规则：

1. 去掉 `.npz`，按 `__` 切成 3 段。
2. 第 1 段 = 被试（`fgw-0917`，汇总时去掉连字符统一成 `fgw0917`）。
3. 第 2 段再按 `-` 切：第 1 个是日期、第 2 个是 **hand**、第 3 个（若有）是 run。
4. 第 3 段是时间戳。

### 1.2 文件夹名为什么不可靠（不用它定手别）

文件夹名形如 `{subject}_{date}_{后缀}`，后缀五花八门、且**不等于手别**：

- 有的是手别：`fgw0917_0502_left`、`ghd1108_0502_right`
- 有的是采集批次/设备：`hzy1217_0501_run1`、`ghd1108_20260513_lenovo`、`..._redmi`、`..._yp9000`
- 有的只是日期：`lah0708_20260519`、`zyb0201_20260518`
- **混合目录**：`pose_20260520-0522_run1` 一个目录里混了多个被试（文件名里能看到 `ghd-1108` 等），目录名 `pose_...` 完全不代表被试。

所以只有文件名内的 `-left` / `-right` 才是可信的手别来源。

### 1.3 无法解析的文件（手别 = UNKNOWN）

文件名形如 `{date}_{timestamp}.npz`（如 `20260513_143928.npz`），**名内既无被试也无手别**。这类共 **840 个**，处理方式：

- 被试：从所在文件夹名前缀兜底（如 `ghd1108_20260513_lenovo` → `ghd1108`）。
- 手别：记为 `UNKNOWN`，**用于实验前必须另行确定左右手，否则弃用**。

## 3. 注意事项（实验前必读）

1. **手套版本是被试之外的第二个域偏移**。文件名里出现 `_v33` / `_v71` / `flat` 等后缀，是手套硬件版本 / 校准模式的差异。做被试无关实验时，建议先固定到同一版本（例如只用纯 `left`/`right`、排除带版本后缀的文件），否则会把硬件差异和个体差异混在一起。

2. **840 个无手别文件不能直接用于左右手相关实验**。其中 **ljx0904、yxf0320、zxd0310 三个被试完全没有手别信息**；其余被试也各有一部分。需要时先人工 / 另据确定左右手。

3. **协议一致性未核对**。本盘点纯按文件名整理，**没有读取文件内容**。带 `run1`、设备名（lenovo/redmi/yp9000）、晚期日期的目录不保证都是同一套 **18 手势**协议，正式实验前应抽查确认。

4. **左手数据池充足、右手偏少**。左手 3276 文件、右手仅 1247。跨被试（LOSO）实验若以左手为主，可选样本量 ≥100 的被试：myy0129、wxg0901、ghd1108、pkj0309、hzy1217、lsh0126、wyl0101、fgw0917 等十余人。

5. **被试名归一**。文件名内被试写作 `fgw-0917`，汇总表统一去连字符为 `fgw0917`；两种写法指同一人。

## 4. 实验数据组（2×2 因子：被试数 × 手数）

为方便对比"单人/多人"和"单手/双手"对聚类的影响，预先切了四个数据组，已建成 symlink 池。
成员清单见 [../data_groups.csv](../data_groups.csv)（每文件一行：group / subject / hand / src_dir / fname）。

**设计原则**：

- 单人组固定用 pilot 被试 **fgw0917**；多人组在单手/双手之间用**同一组被试**（fgw0917 + pkj0309 + wjh0111 + wyl0101，这 4 人左右手都有），使四组可直接横向对比，且 fgw0917 嵌套在全部四组里。
- 统一只保留 **hand 恰为 `left`/`right`** 的文件，**排除手套版本变体**（`v33`/`v71`/`flat`）和无手别文件，避免硬件域偏移混入（见 §3）。

| 数据组 | 池目录 | 被试 | 手 | 文件数 |
|---|---|---|---|--:|
| 单人单手 | `work_pool_single_single` | fgw0917 | left | 160 |
| 单人双手 | `work_pool_single_both` | fgw0917 | left + right | 260 |
| 多人单手 | `work_pool_multi_single` | fgw0917, pkj0309, wjh0111, wyl0101 | left | 723 |
| 多人多手 | `work_pool_multi_both` | fgw0917, pkj0309, wjh0111, wyl0101 | left + right | 1252 |

各组每被试×手的文件数细分（均为纯 left/right）：

- 单人单手：fgw0917 L160
- 单人双手：fgw0917 L160 / R100
- 多人单手：fgw0917 L160、pkj0309 L246、wjh0111 L126、wyl0101 L191
- 多人多手：以上四人 L + R（fgw R100、pkj R120、wjh R189、wyl R120）

### 4.1 多人左手扩展池（被试数缩放：4 → 6 → 全部）

为研究"被试数增加对跨人聚类的影响"，在左手上另切两个规模递增的池。同样**只保留纯 `left`**（排除 `v33/v71/flat` 变体与无手别文件）。

| 数据组 | 池目录 | 被试 | 文件数 |
|---|---|---|--:|
| 4 人左手 | `work_pool_4users` | fgw0917, ghd1108, hzy1217, lsh0126 | 429（主实验，见汇报文档） |
| 6 人左手 | `work_pool_6users_left` | 上述 4 人 + myy0129, wxg0901 | 1678 |
| 全部左手 | `work_pool_all_left` | 23 名有纯左手数据的被试全部 | 3024 |

- **嵌套设计**：6 人池 = 主实验 4 人集的超集（再加文件量最大的 myy0129、wxg0901），可直接做 4→6→全部 的规模对比。
- 全部左手池含 23 名被试（每人纯左手文件数见 §2 / `data_summary.csv`）。
- 这两个池的成员清单同样写入 [../data_groups.csv](../data_groups.csv)（group = `6users_left` / `all_left`）。

### 4.2 跑某一组（池已建好，跳过 pool 步骤）

```bash
# 例：多人单手，k=18
POOL=work_pool_multi_single OUT=out_multi_single ./pulse.sh segment
POOL=work_pool_multi_single OUT=out_multi_single ./pulse.sh cluster 18
POOL=work_pool_multi_single OUT=out_multi_single ./pulse.sh qc
```

**聚类粒度（`GROUP_BY`）与被试无关目标相关**：

- `subject-hand`（默认）：每个 (被试,手) 各自聚类——单人组天然如此；多人组会得到每人各一套簇。
- `all`：所有段合到一起聚类——这才是"被试无关"设定，但会受被试身份信号污染（见 [METHOD.md](METHOD.md) 与项目结论）。多人组研究被试无关时用：
  ```bash
  POOL=work_pool_multi_both OUT=out_multi_both GROUP_BY=all ./pulse.sh cluster 18
  ```
- `hand`：跨被试按左/右手合池（双手组研究左右手时用）。

### 4.3 重建数据组池

所有数据组池都是按 §1 规则从 `data_inventory.csv` 筛选（纯 left/right、排除变体与无手别）后 symlink 而成。改动成员口径后重跑生成脚本即可覆盖各 `work_pool_*` 与 `data_groups.csv`。

---

## 5. 如何重新生成

两张 CSV 由扫描 `processed_data` 全量 `.npz`、按 §1 规则解析得到（不读文件内容，秒级）。重扫只需重跑生成脚本即可覆盖 `data_inventory.csv` / `data_summary.csv`。
盘点口径若变化（例如把手套版本拆开、或纳入 UNKNOWN 的人工手别），改解析规则后重跑即可。
