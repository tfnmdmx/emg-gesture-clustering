## 1. 核心思路

**pose-speed 当脊柱定义所有 onset/边界，EMG envelope 做三件事：确认 hold、补切（split）连续持姿、并对"被合并的背靠背持姿"主动否决欠切。** 协议是 运动→持姿→运动→持姿，且**没有公共 neutral**——连续两个 hold 是两个不同的非 neutral 成形姿态。因此 hold 必须按"低 pose-speed **AND** 低 EMG"检测（运动停了 + 肌肉松了），绝不能用"离某 neutral 的距离"。pose-speed 锐利、能抓 EMG 漏掉的慢/被动运动，所以由它画 onset；但当两个连续持姿之间姿态没回中、pose-speed 谷很浅时，pose 无法分开它们——而 **EMG 会在两次运动之间回落到 baseline**（肌肉放松），这是唯一能分开"连续非 neutral 持姿"的物理信号。所以 EMG 专职在 pose 合并出的 run 内部按"肌肉放松最深处"补切。这是**非对称融合**（不是对称投票）：pose 决定"哪里有运动/在哪 settle"，EMG 决定"两个被合并的运动之间该不该切、切在哪"，绝对关节位移 gate 决定"这是不是真手势"。

**为什么选这个核心而不是另外三个：** EMG-primary（设计A）把所有边界绑死在 EMG burst 列表上，而本数据**已记录的主导失效模式恰恰是 EMG-silent 的轻柔慢手势**（jm-0503 有 rest-level 低 EMG 的温和动作），一个漏掉的 burst 会同时丢一个手势并把它的两个邻居融成一段——方向错了。2-state HMM（设计C）的 Viterbi/emission 核在本仓库**根本不存在**（无 `viterbi`/`gauss_logpdf`，env 里没装 `hmmlearn`），且把 HOLD 锚在 p40（56% 样本是静止）会复活 velocity-valley 过切，复杂度与未验证必要性不划算。pose-primary 纯阈值（设计B）方向对，但单阈值 `static_motion_intervals` 在死区会让带肌张力的微抖持姿"永不闭合 run"而欠切。本设计取 D 的双信号互补脊柱，补上死区相对-settle 闭合、短 NaN 修复、R2 切点对齐与门控、背靠背持姿 EMG-否决（R7）。（**实测注**：R7 落地为默认关的开关；"可冷启动的非循环校准 DAG"未建——见 §0 与 §6.0；阈值改回 `robust_threshold` 自适应而非纯绝对阈值。）

## 2. 信号管线

两路一维信号，都在 2000 Hz EMG 采样轴上（pose 已由 `io_utils.load_npz` 线性插值上采样到该轴，物理带宽 ~75 Hz）。**全部复用现有函数，不改。**

| 信号 | 函数 | 单位 | 平滑窗 | NaN 处理 |
|---|---|---|---|---|
| `env` EMG 包络（确认/补切/否决） | `segmentation.emg_envelope(emg, fs, smooth_ms=150)` | a.u.（逐通道中位数去基线后跨 16ch 的 RMS） | 150 ms（=300 样本） | **内部 `nanmedian/nanmean`，EMG 的 NaN 已被正确吸收**——单通道 NaN 不破坏基线、整列 NaN 经 `nanmean` 跳过。**所以 EMG 路径无需额外 NaN 修复**，只对 pose 修复（见下）。 |
| `spd` pose-speed（脊柱） | `pose_segmentation.pose_speed(ja_filled, fs, pose_smooth_ms=250)` | **rad/s**（20 关节 `‖dθ/dt‖₂`；`io_utils.load_npz` 已把 Manus deg→rad，故全程 rad） | 250 ms（=500 样本） | 见下面的"短 NaN 修复"——必须在 `pose_speed` 前填，否则 `uniform_filter1d` 把单帧 NaN 抹成 ±250ms（~500 样本）的 NaN-speed 空洞，被当作"运动"。 |

**新增 / 派生（一次性）：**

- **短 NaN 修复（关键鲁棒性修复，先于 `pose_speed`）**：`ja_filled = interpolate_short_nan_gaps(ja, fs, max_gap_s=0.20)`。语义精确定义（见 §10 helper 表）：
  - **逐通道（per-channel）独立**处理——单关节遮挡只修该列，不要求 20 关节同时有效；这样常见的"单指被另一只手挡住"不会拖累其它 19 个关节。
  - 对每列，找出连续 NaN run；**run 长度 ≤ `max_gap_s·fs`（0.20s=400 样本）且两端都有有限锚点**时，用两端线性插值（`np.interp`）填。
  - **录制头/尾的 NaN（无左/右锚点）不外推**，保持 NaN；长于 `max_gap_s` 的内部 gap 也保持 NaN。
  - 残余 NaN → `pose_speed` 产生 NaN-speed → `pose_hysteresis` 中 `np.isfinite(v)` 失败 → **按"运动"处理**（安全默认：未知区间不能升格成 settled hold）。
  - **实测注**：`interpolate_short_nan_gaps(ja, fs, max_gap_s=0.20)` 已落地（无 `min_finite_frac` 参数；它只读 `nan_max_gap_s`）；`pose_nan_frac` 仍由 `recordings.csv` 记录，但**没有 `review_flag='nan'` 这条 QC 标**（实际 `review_flag ∈ {long, nohold, slow, long_static, ''}`）。
  - **为什么这步让 NaN-in-hold 单测通过：** "hold 内单帧掉帧不融两段"之所以成立，**正是因为这一步在 diff/smooth 前把单帧填掉**了；若不填，那一帧会变成 0.25s 的 NaN-speed 空洞被判为运动，把一个 hold 劈成两半（=融合两段的前置欠切）。对照单测：一个 **> `nan_max_gap_s` 的长 gap** 仍（正确地）被当作运动、不被填、那 0.25s speed 仍被污染——这是已知且可接受的安全行为（见 `tests/test_action_segmentation.py::test_interpolate_short_nan_gaps_fills_short_keeps_long`）。
- **`rest = np.nanmedian(ja, axis=0)`**（20-向量，rad）：**仅用于 apex 帧的偏离排序**，绝不当 neutral 检测器（协议无 neutral）。**实测**：`segment_recording` 已用 `np.nanmedian`（nan-aware）；`features.apex_index`/`apex_pose_feature` 也已 nan-aware。
- **关节位移（gate 特征，非时间序列）**：任意窗 `[a,b)` 的 `pose_range = ‖nanmax(ja[a:b]) − nanmin(ja[a:b])‖₂`（rad）。**NaN-fraction guard（关键安全修复）**：`nanmax/nanmin` 在**全/几乎全 NaN 窗**上返回 NaN，而 `NaN < pose_min_range` 为 `False`——会让一个 NaN 满布的 MOTION run **错误地通过** gate（与安全默认相反）。故 gate（`seg_range_ok`）实现为：
  ```
  finite_frac = mean(all-finite-rows in ja[a:b])
  if finite_frac < min_finite_frac(=0.5):  return DROP   # NaN 太多→丢/打 'nan'，不放行
  rng = norm(nanmax - nanmin);  return DROP if (not isfinite(rng) or rng < pose_min_range)
  ```
  用于录制级（`rec_pose_range`）和 per-segment 绝对 gate，两处共用此 guard。
- **全局 xcorr lag（设计想移除，实测未移除）**：设计本想"不计算全局 xcorr lag"（已确认它在准周期数据上锁到反相：lag≈−0.6s, corr≈0.22, 0/143 ok）。**但落地未删**：`segment.py:233` 仍调 `qc.estimate_emg_pose_lag`/`qc.lag_status`，`recordings.csv` 仍写 `emg_pose_lag_s`/`emg_pose_corr`/`lag_flag` 三列。而 §3 R6 的"局部 per-event lag"则**从未实现**（无 `onset_lag_s`/`emg_pose_lag_local_s`）。下文 R5/R6/§9#10 的局部-lag 设计均属 superseded/未建。

## 3. 检测算法（状态机 + 显式融合规则）

两台**独立**状态机，融合前互不可见对方输出。

### Detector A — EMG burst（直接复用 `segmentation.segment_emg`，不改）
`auto_thresholds` 在 `env` 上做 Otsu：rest 模 + action 模，`enter = rest_center + 0.8·(valley−rest_center)`，`exit = rest_center + 0.4·(valley−rest_center)`（迟滞 enter>exit）。2-state `REST↔BURST`：`env>=enter` 进 BURST，`env<exit` 回 REST。`filter_segments` 合并间隔 `<min_rest_gap_s` 的 burst、丢弃短于 `min_action_s` 的 burst。
> 输出：filtered burst 区间列表 `bursts=[(bs,be),…]`、`enter`、`exit_e`。
> **EMG-rest 的唯一定义（全文统一）：** `EMG-rest = env < exit_e`（连续 envelope 阈下区），**不是** "filtered burst 的补集"。理由：`filter_segments` 会合并/丢弃 burst，其补集会把"被丢弃的 sub-`min_action` 激活"也算进 rest，而那些区间 env 其实 `>= exit_e`（肌肉并未放松）。R3 的 hold 确认、R2 的"干净 rest 间隙"、R7 的"hold 内 EMG 活动"**三处都用 `env<exit_e`**，不混用补集。
> 注意校准措辞要对齐真实代码：阈值锚点是 `rest_center = median(env[env<=valley])`（仅 sub-valley 样本的中位数），**不是**整段 env 的中位数。

### Detector B — pose 静止/运动迟滞机（已落地 `action_segmentation.pose_hysteresis`，替换单阈值 `static_motion_intervals`）
2-state 迟滞机 `STATIC↔MOVING`，阈值单位 **rad/s**（关节角加载后即 rad）。**实测反转：阈值默认不是固定绝对值，而是逐录制自适应。** `resolve_move_thresholds` 在 `auto_move_thresh=True`（默认）下用 `move_enter = robust_threshold(spd, pose_pct=35, pose_mad=1.5)`、`move_exit = move_exit_frac(0.5)·move_enter`。设计原稿主张"绝对阈值修 robust_threshold 降到噪声底的 A5 失效"——但实测发现 pose-speed 量级跨录制 ~4×（jm-0503 detect~2.8 vs hzy~10.4 rad/s）且 EMG-rest 在本数据不是干净 hold 代理，故**回到 robust_threshold 自适应**，A5 的 near-static 失效改由下游 R0 绝对位移 gate 兜底。固定 `move_enter=radians(60)`/`move_exit=radians(25)` 仅在 `--no-auto-move-thresh`（消融）或 `robust_threshold` 非有限/≤0 时作回退。

- **STATIC→MOVING**：`spd >= move_enter`（auto；回退 `radians(60)`）。
- **MOVING→STATIC（双判据闭合，关键修复死区欠切）**：满足以下**任一**并持续 `>= min_static_s`(0.35 s)：
  1. **绝对**：`spd <= move_exit`（auto = `0.5·move_enter`；回退 `radians(25)`）；**或**
  2. **相对-settle**：`spd <= max(move_exit, settle_frac·peak_run)`（`peak_run` = 本 run 内 spd 峰值，`settle_frac`=0.25）。
  实测 `settle = min(0.9·move_enter, max(move_exit, settle_frac·peak_run))`——**上界还被 `0.9·move_enter` 钳住**（否则下个样本会重新触发运动），下界被 `move_exit` 钳住。因此既能闭合落在 `move_exit`–`move_enter` 死区的"带张力微抖持姿"，又不会复活"相对阈值降到噪声底造 phantom"的 A5 bug。
- MOVING run 短于 `min_motion_s`(0.20 s) → 丢弃（抖动）。STATIC run 短于 `min_static_s`(0.35 s) → 不算真 hold，**并入相邻 MOVING run**（=死区/速度凹陷的 dip-merge，直接消灭 velocity-peak 的 2× 过切）。
> 输出：交替的 MOTION run `[ms,me)` 与 HOLD 平台 `[hs,he)`。

### 显式融合规则（pose 脊柱，EMG 确认+补切+否决）

- **R0 绝对位移 gate**：`rec_pose_range < pose_min_range`(=`radians(15)`)（经 `seg_range_ok` 的 NaN-fraction guard）→ 整段录制静止（`dbg["pose_static"]=1`），返回 0 段（异常：长时间静止）。每个 MOTION run 若窗内 gate 判 DROP → 丢弃（噪声 bump / NaN 满布）。
- **R1 onset 列表**：候选 motion onset = Detector B 每个 MOTION run 的起点 `ms`。pose 当脊柱，因为它抓 EMG 漏的慢/被动运动（binding fact）。
- **R2 EMG 补切（仅对 pose 合并的超长 run）**：对每个 MOTION run `[ms,me)`，只有当**同时满足**：(a) run 长 `> pose_long_seg_s`(2.5 s)（永不 settle）**且** (b) run 内 burst 中心 ≥2 个**且** (c) 这些 burst 之间至少有一个 `>= min_rest_gap_s` 的**干净 EMG-rest 间隙**（`env<exit_e` 连续段）——才补切。切点放在该间隙内 `env` argmin（肌肉放松最深处）**再 `snap_to_speed_min` 到最近的 pose-speed 局部极小**（落在真实减速点而非任意中段；带界搜索，见 §10）。每个子段重跑位移 gate，不过则丢。若肌肉持续激活（无 rest 间隙）→ §7 的 valley-split fallback（仅此处允许）。**常规 run 不切**（避免 velocity-peak 过切）。
- **R3 hold 确认 = 一致性（未实现，superseded）**：原设计要算 hold 平台与 EMG-rest 重叠 `>= hold_confirm_s` 的 `both_quiet`/`hold_agreement`。**实测：`segment_recording` 不计算 `both_quiet`/`hold_agreement`，无 `hold_confirm_s` 这条门槛**（该参数也不在 Config 里）。本规则未落地。
- **R4 类型化分歧（部分落地）**：实测只看 **MOTION run** 上的 EMG，命名 `emg_in_motion`：
  - pose MOTION run 内**无** EMG burst（`emg_in_motion=False`）→ **慢/被动运动**：**保留为真段**，`fusion_type='pose_only'`；当其 hold 合格时 `review_flag='slow'`。← 这条直接修复设计A的 EMG-silent 欠切。
  - 有 EMG burst 重叠 MOTION run（`emg_in_motion=True`）→ `fusion_type='both'`（高置信）。
  - **未落地**："EMG-only 等长收缩不产段 + `count_isometric` 记 `n_emg_only`"在 `segment_recording` 中**没有实现**（onset 完全由 pose MOTION run + R2/R7 产生，从不为孤立 burst 造段，所以也无需该计数器）。
- **R5 投票汇总（未实现，superseded）**：`agreement_rate`/`n_pose_only`/`n_emg_only`/`emg_pose_lag_local_s` **均未写入** `recordings.csv`。而设计想"替换全局 xcorr 列"也**未做**——全局 `emg_pose_lag_s`/`emg_pose_corr`/`lag_flag` 仍在（见 §0 / §2）。
- **R6 局部 lag（未实现，superseded）**：`onset_lag_s`/`local_onset_lag`/`local_lag_window` **均未落地**；Config 无 `local_lag_lo`/`local_lag_hi`。
- **R7 背靠背持姿否决（已落地但默认 OFF）**：`_r7_splits` 已实现——一个 **常规长度**（`<= pose_long_seg_s`）的 hold 平台内含一段干净 EMG burst（`>= min_action_s`，前后各有 `>= min_rest_gap_s` 的 EMG-rest）→ 在该 burst 的 `env` argmin → `snap_to_speed_min` 处补切。**但 `enable_r7=False` 是默认**：常规数据上 ~125ms pose 平滑群延迟会把 EMG burst 落进前一个 hold，R7 会过切，故仅在确实欠切的录制手动开。设计原稿把它当"永远在线的核心欠切修复"——已反转为可选消融开关。

> **lag 的混淆说明（仍有解释价值；R6 的局部 lag 列未落地）：** loader `io_utils._align_pose_to_emg` 把 `pose_t` 按 `emg_t[-1]/pose_t[-1]` 重标到 EMG end-time，叠加 pose ~75Hz 上采样 + 250ms 平滑，使 pose-speed 相对 EMG 有**未知的群延迟**——任何"EMG 领先 pose ~50ms"里有一部分是插值/时钟重标伪影，**不是生理**。因此 `snap_window_s` 的设值理由从"生理 EMG-lead"弱化为"覆盖 pose 平滑群延迟（~125ms）+ 半 pose 帧 + 一点裕度"。**实测注**：R6 局部 lag 列、以及 onset 取 `min(pose_foot, emg_enter)` 的 EMG-enter 耦合**均未落地**——`segment_recording` 的 onset 只走 `snap_to_motion_foot`（回溯到 pose rising-flank 脚），不读 EMG enter。`local_lag_window`/`onset_lag_s` superseded。

## 4. 利用规则结构（交替先验当**主动约束**，不只是副产品）

协议的 静止↔运动 **严格交替**是硬约束。它不只是 Detector B 输出的形状（那只是被动副产品），还被 R7 升级为**能否决错误切分的主动规则**：

1. **交替（被动，by construction）**：Detector B 输出按构造交替 MOTION,HOLD,MOTION,…；段由"一个 MOTION run + 紧跟的 HOLD 平台"组成，右边界 = 下一个 onset。相邻段**无缝平铺时间轴**（`action_N.end == action_{N+1}.start`），每个成形持姿被恰好一段独占——这保证**不会过切**，但**不保证不欠切**。
2. **dip-merge 当先验**：单次运动内部的速度凹陷（reach→curl 两相手势、张力微抖）短于 `min_static_s` → 不闭合 run → 不产生伪 onset。这把"一个自然手势"钉成一段。
3. **R7：交替先验当 VETO（已落地为可选开关，默认 OFF）**：本协议最危险的失效**不是过切而是背靠背持姿欠切**——两个不同成形姿态之间几乎没有可见 pose 位移（手没回中、只换了发力），pose-speed 谷浅到不闭合 run，于是两个 hold 被融成一段、其间的发力 blip 被 dip-merge 吞掉。R7 (`_r7_splits`) 把它变成否决：**任何常规长度 hold 平台内出现干净 EMG burst（`>= min_action_s` 且前后有 `>= min_rest_gap_s` EMG-rest）→ 强制在该 burst 处切开**，即使 run 长度 `< pose_long_seg_s`（R2 触发不到）。与 R2 互补。**实测反转：`enable_r7=False` 默认关闭**——常规数据上 pose 平滑群延迟把 burst 落进前一个 hold 导致过切，故 R7 不是"永远在线的硬否决"，而是个别欠切录制才开的开关。
4. **EMG 放松当"真边界"判据**：交替先验说"两段之间应有一次肌肉放松"。R2/R7 都只在"肌肉确实发力过且放松过"（干净 EMG-rest 包夹的 burst）时才补切——没有放松证据就不切，避免把一个手势的两相误切。
5. **计数先验当 sanity**：常规录制 ~每 119 s 出 ~35–50 段，仅用于 §9 体检，不门控。

## 5. 段定义与边界（样本级精确）

**一段 action = 一个 MOTION run + 其紧跟的真实稳定 hold，右边界落在下一次运动 onset。无 50 ms pad、无 0.5 s hold 上限。**

对第 k 段（onset 经 R2/R7 补切后）：

实测落地的字段名是 `start/end/motion_start/motion_end/hold_start/hold_end/apex`（dict 键，非 `*_sample`）：

```
start         = s = onset_k                    # snap_to_motion_foot(onset) 后的脚
motion_start  = s                              # 实测 motion_start 直接 = s（无独立 ms 列）
motion_end    = me = _motion_end_in(...)       # 首个 pose-settle 后、钳进 [s+1, e-1]
hold_start    = me
hold_end      = e = onset_{k+1}（末段 = n）    # 下一段 onset = 真实 hold 右界
end           = e
apex          = apex_index(ja, hs, he, rest, fs)   # 在 hold 窗内取最大偏离-rest 帧
```

- `apex` 用现有 `features.apex_index`，**优先在 `[hold_start, hold_end)`** 内取**平滑后最大关节偏离 rest** 的帧 = 最成形的姿态瞬间，**不是**峰速帧。
- **apex 空窗守护（实测三层 fallback）**：`features.apex_index` 在空窗会 `raise ValueError`，故 `segment_recording` 三层守护：
  1. `he - hs >= 2` → `apex = apex_index(ja, hs, he, rest, fs)`（hold 窗内）；
  2. 否则 `he - s >= 2` → `apex = apex_index(ja, s, he, rest, fs)`（退用整段 `[start, hold_end)`）；
  3. 否则（被下一 onset 压成 ~1 帧 / 录制末尾 mid-motion）→ `apex = s`（运动起点）。
  **`review_flag` 与 apex 守护无耦合**，是另行按 `motion_dur`/`hold_dur` 判定的（见下文 §5 末"flag 实测逻辑"）——设计稿"空窗就打 `review_flag='long'`"的耦合**不成立**。

**边界精确放置（实测）：**
- **START（motion onset）**：`spd` 上穿 `move_enter` 处，由 `snap_to_motion_foot` **回溯**到其前最近的 `spd<=move_exit` 样本（rising flank 的脚），把整段成形运动收进段内。回溯窗为 `[s−snap_window_s·fs, s]`；**窗内找不到（含录制起始即在运动中）→ 钳到搜窗左端 `max(0, s−w)`，不报错**。**实测注**：onset 不取 `min(pose_foot, emg_enter)`——EMG-enter 耦合未落地，onset 纯由 pose 脚决定。
- **END / 下一 START 共享**：同一 onset 列表相邻项共享边界 → 无缝无重叠。
- **HOLD 内界**（`motion_end`/`hold_start`）：实测由 `_motion_end_in(motion_runs, s, e, min_motion)` 取**首个 `me > s` 的 pose-settle 闭合点**并钳进 `[s+1, e-1]`；纯 hold 段（R7 在 hold 内切出的）给一个名义短 motion `s+min_motion`。
- **R2/R7 补切边界**：burst 间/burst 内 `env` argmin → `snap_to_speed_min` 到最近 pose-speed 局部极小（带界，窗内无极小则退回 anchor 本身）。
- **退化保护**：钳 `motion_end ∈ [s+1, e−1]`；apex 空窗守护见上。

**flag 实测逻辑（`review_flag`，按优先级）：** `motion_dur > pose_long_seg_s` → `'long'`；elif `hold_dur < min_static_s` → `'nohold'`；elif `not emg_in_motion` → `'slow'`；elif `hold_dur > max_hold_s` → `'long_static'`；else `''`。**无 `'nan'`**。

**首段 / 末段 / mid-motion 边缘（显式规定）：**
- **首段**：协议是 move→hold，**首事件是无前置 hold 的 motion，正常**。若录制开局即在运动中（`spd[0] >= move_enter`）：`pose_hysteresis` 的 STATIC 分支在 `t=0` 即触发（`v>=move_enter`），`start=0`；`snap_to_motion_foot` 回溯找不到 `<=move_exit` 的脚 → 钳到 0。
- **末段**：协议末事件是无后继 onset 的 hold。**实测**：末段 `end = n`（直接用录制长度 `n`，不调 `last_hold_end`——该 helper 未落地）。若录制**末尾 mid-motion**（最后一个 MOVING run 被 `pose_hysteresis` 的 tail 子句以 `len(spd)` 闭合，没有后继 hold）→ `hold_start≈hold_end` → 触发上面的 **apex 三层守护**（最终 `apex=s`），不崩溃；`review_flag` 另由 `motion_dur`/`hold_dur` 决定（mid-motion 长段→`'long'`，或 `'nohold'`）。

### 6.0 校准依赖 DAG（superseded：冷启动 DAG 未落地）

> **实测反转（整段 §6.0/§6.1 多为未建）：** 落地的阈值方案是 `auto_move_thresh=True`（默认）下逐录制 `robust_threshold(spd, pose_pct=35, pose_mad=1.5)` 派生 `move_enter`、`move_exit=0.5·move_enter`。**没有 `emg_label/calib.py`，没有 `cold_start_pose_thresholds`，没有"EMG-rest-gated pose-speed 冷启动"那套 DAG。** 下面三层 DAG 当作设计史保留；第 1 层的"仅由 EMG 派生 pose 阈值"被实测拒（`resolve_move_thresholds` docstring：EMG-rest 不是干净 hold 代理）。所有数值单位应为 **rad/s** 而非文中的 deg/s。第 0 层多个常量也**不在 Config 里**（`hold_confirm_s`/`local_lag_window` 未建；`min_action_s=0.4`/`min_rest_gap_s=0.2`/`pose_min_range=radians(15)`/`pose_long_seg_s=2.5`/`max_hold_s=4.0`/`nan_max_gap_s=0.2`/`min_finite_frac=0.5`/`snap_window_s=0.15`/`min_static_s=0.35`/`min_motion_s=0.2`/`settle_frac=0.25` 确在 Config）。

旧表的多条配方**互相循环**（`move_exit` 要 confirmed hold，而 confirmed hold 经 R3 又要 `move_exit`；`min_static_s`/`min_motion_s` 要已切好的 hold/motion 时长）。冷启动时这些量都**还不存在**。原设计提出下面三层 DAG，**但实测未采用**：

- **第 0 层 — 常量（不校准，固定）：** `fs=2000`, `smooth_ms=150`, `pose_smooth_ms=250`, `settle_frac=0.25`, `min_action_s=0.40`, `min_rest_gap_s=0.20`, `emg_enter_k=0.8`, `emg_exit_k=0.4`, `pose_min_range=15`, `pose_long_seg_s=2.5`, `max_hold_s=4.0`, `nan_max_gap_s=0.20`, `min_finite_frac=0.5`, `snap_window_s=0.15`, `local_lag_window=[-0.30,+0.05]`, `min_static_s=0.35`, `min_motion_s=0.20`, `hold_confirm_s=0.30`。
  - **`min_static_s`/`min_motion_s`/`hold_confirm_s` 改为常量**（不再写"略低于 hold/motion 时长 P5"那种循环配方）。它们是**纯时间裕度**，由平滑窗决定而非由切分结果决定：`min_motion_s=0.20` ≥ 250ms 平滑窗能可信分辨的最短运动；`min_static_s=0.35` > `pose_smooth_ms` 以确保 dwell 测的是真平台不是平滑余晖；`hold_confirm_s=0.30` = `min_static_s − pose_smooth_ms/2`（0.35−0.125≈0.225，向上取 0.30 留裕度）——**这就是旧表说的"减平滑余量"，现在给出明确数字**。这些常量在 §9 体检里**事后验证**（#3 #4），而**不是**靠它们去校准。
- **第 1 层 — 仅由 EMG 派生（superseded：实测拒用）：**
  原设计想 Detector A 独立于 pose，先跑它拿 EMG-rest 区（`env<exit_e`），再用 EMG-rest 门控 pose-speed 取统计派生 pose 阈值。**实测发现该方案不成立**（`resolve_move_thresholds` docstring：低 EMG 时 pose-speed p95 仍 ~17 rad/s，gentle 手势在 rest-level EMG 下发力），故改回 `robust_threshold` 自适应。下面伪代码是未建的设计史：
  ```
  # cold_start_pose_thresholds(emg_list, ja_list, cfg) -> (move_enter, move_exit)
  rest_spd = []                          # 所有录制里"EMG 说肌肉松了"的样本的 pose-speed
  for emg, ja in calib_recordings:
      env = emg_envelope(emg, fs, 150)
      _, exit_e = auto_thresholds(env, 0.8, 0.4)
      spd = pose_speed(interpolate_short_nan_gaps(ja,fs,0.20), fs, 250)
      rest_mask = (env < exit_e) & isfinite(spd)
      rest_spd += list(spd[rest_mask])
  move_exit  = ceil(percentile(rest_spd, 99))      # EMG-rest 平台内 pose 噪声的 P99
  move_enter = 3 * percentile(rest_spd, 95)         # 落在 hold 噪声与最慢真运动之间
  assert move_exit < move_enter                      # 否则回退默认 25 / 60
  ```
  默认 `move_enter=60 deg/s` / `move_exit=25 deg/s` 是在校准集（见 §6.1）上跑出的典型值，作为 `assert` 失败时的回退。**注意：这里完全不需要 confirmed hold 或任何已切段**——EMG-rest 把"肌肉松了"的时刻独立标出来，那些时刻的 pose-speed 就是 hold 噪声的样本，无需先有 hold。
- **第 2 层 — 可选迭代精修（不是冷启动必需，仅当第 1 层阈值在 §9 体检不达标时）：** 用第 1 层阈值跑一遍 `segment_recording` 得到初版 motion/hold 段，再用这些段的经验分布**复核**（不是重设）常量：`P99(spd within emitted holds)` 应 `≈ move_exit`、`P5(emitted hold duration)` 应 `> min_static_s`、`P5(emitted motion duration)` 应 `> min_motion_s`。若严重偏离则手调并重跑——**最多 1–2 轮**，不做自动闭环（避免相对阈值漂移）。

## 7. 异常段处理（次级 post-processing）

主流程为**常规录制**调优；异常仅在 base 切分后兜底，绝不内联特判。

1. **长时间静止 / phantom（R0 绝对 gate）**：`rec_pose_range < pose_min_range`(=`radians(15)`) → 0 段，`pose_static=1`。per-window gate 判 DROP（含 NaN 满布）→ 丢该 run。**注**：move 阈值本身仍走 robust_threshold 相对法，near-static 失效靠这个绝对 gate 兜底（不是用绝对 move 阈值）。
2. **动作太快无停顿（超长 run）**：MOTION run `> pose_long_seg_s`(2.5s) 时 `review_flag='long'`（按 `motion_dur`）。
   - 若内含 ≥2 burst 且有干净 EMG-rest 间隙 → R2 在肌肉放松最深处补切（snap 到 pose 谷）。
   - 若肌肉持续激活（无 rest 间隙）→ **仅在此 flagged run 内**退回 `pose_segmentation.velocity_peak_segments`。**注意陷阱：** `velocity_peak_segments` 内部 prominence 用**整段信号的 MAD** 自算，**忽略传入的 `detect_thr`** 那一项——在 saturated（一直高速）的异常 run 上 MAD 极小，会**过切恰好这个异常 run**。因此 fallback 须：(a) 把 `detect_thr` 传为 `move_enter`（约束 height）；(b) **在调用前对该 run 内的 speed 子段单独算 MAD/prominence floor**，或直接传一个**绝对 prominence 下限**（=`0.5·move_enter`），不依赖 saturated 段的 MAD；(c) 每个子段重跑位移 gate，不满足则**保留为一整段 'long'**（宁可一段诚实长段，也不要 2× phantom 切——符合 §9#9"切成 >1 但诚实"）。
3. **背靠背持姿欠切（R7，默认 OFF）**：常规长度 run 内 hold 平台含干净 EMG burst → 强制切（§4.3）。**实测 `enable_r7=False`**，仅个别欠切录制开。
4. **超长 hold**：hold `> max_hold_s`(4s) → 保段，`review_flag='long_static'`，不影响边界。
5. **慢/被动（pose_only，R4）**：保段，`review_flag='slow'`。
6. **等长收缩（emg_only，R4）**：**未实现**——`segment_recording` 不为孤立 burst 造段，也无 `count_isometric`/`n_emg_only`。
7. **NaN 遮挡**：先短 NaN 修复（§2，逐通道、头尾不外推）；残余长 NaN 按运动；位移 gate 有 NaN-fraction guard。**无 `review_flag='nan'`**（`pose_nan_frac` 仍记入 `recordings.csv`）。
8. **lag QC（设计想移除，实测未移除）**：全局 xcorr `emg_pose_lag_s`/`emg_pose_corr`/`lag_flag` **仍在 `recordings.csv`**；局部 lag/`agreement_rate` 列**未落地**。
9. **无真 hold（实测新增 flag）**：`hold_dur < min_static_s` → 保段，`review_flag='nohold'`。

## 8. 为什么不默认用 velocity-peak 谷底切

velocity-peak（一个 pose-speed 峰一段、在谷底切超长 run）在**常规数据上 2× 过切**（clips/bursts=2.0）：一次自然手势常是两相（reach→curl）或带张力微抖，会产生 ≥2 个速度峰，于是被切成约 2 段，duration std 退化到 ~0.136（在切波形而非切语义）。本协议的真边界是"两次成形持姿之间"，由 dip-merge（短凹陷不闭合 run）+ EMG 放松证据（R2/R7）界定，而非每个速度峰。所以谷底切**只保留**给 §7.2 内部已 flagged 的"永不 settle 连续手势且无 rest 间隙"的退路；常规路径绝不使用，且调用时须按 §7.2 规避其 MAD-prominence 自过切陷阱。

**#11 度量错配警告（关键，必须读）：** `cluster_traj.clip_traj_feature(ja, ms, me, …)` 的特征**只取 `motion_start_sample → motion_end_sample`（MOTION run 轨迹），完全不看 hold**。**实测注**：`cluster_traj.py` 现已是**一等公民轨迹通道**（pulse.sh `cluster-traj`、读 index.db、写 `cluster_runs/{run_id}/`）；另一条 APEX 通道是 `cluster.py`，它聚的是 **STATIC apex 成形姿**（经 `features.clip_features_for`/`clip_apex_feature`，读各录制 `OUT/features/{stem}.npz` 的 clip-keyed apex 缓存、缺失则 nan-aware 重算）——所以 APEX 路径其实**已经在吃 hold 内的 apex 姿**，下面的"silhouette 看不到 hold"主要针对轨迹通道 `cluster_traj`。本设计的核心卖点是"捕获真实 hold"，对 `cluster_traj` 而言 silhouette 看不到 hold；三选一处理（设计取 **(a)+(b)**）：
- **(a) 明确声明** #11 仅验证 motion 边界，**不**当 hold 工作的验收门槛；
- **(b) 改 `cluster_traj`** 加一路 apex/hold 特征：在 `clip_traj_feature` 旁新增 `apex_pose_at(ja, apex_sample)`（取 apex 帧 ±50ms 中位姿，即复用 `features.apex_pose_feature` 的成形姿）拼到轨迹特征后，**这样 silhouette 才真正吃到 hold 的成形姿**；以此版 silhouette 作 hold 工作的下游验收。
- (c) 备选：若不改 cluster_traj，则 #11 从主验收门槛**降为旁证**。
- **结论**：#11 作为门槛**只对 (b) 改造后的特征成立**；未改造前 silhouette ≥0.33 仅为 motion 边界旁证，不算 hold 捕获的证据。

### 10.3 新 helper 函数定义与边缘守护（伪代码引用的全部 helper，逐一定义）

实测落地的 helper（`action_segmentation.py` 真实名字）：

| helper（实测名） | 定义 + 边缘守护 |
|---|---|
| `interpolate_short_nan_gaps(ja, fs, max_gap_s=0.20)` | 逐列找连续 NaN run；run≤`max_gap_s·fs` 且两端有限 → `np.interp` 填；头/尾无锚 NaN 不填；返回 `ja_filled`。**无 `min_finite_frac` 参数**。 |
| `seg_range_ok(ja, a, b, pose_min_range, min_finite_frac=0.5)` | NaN-fraction guard（§2）：`b<=a` 或 `finite_rows.mean()<min_finite_frac` → False；`rng=norm(nanmax−nanmin)`；`isfinite(rng) and rng>=pose_min_range`。 |
| `snap_to_motion_foot(spd, s, fs, move_exit, snap_window_s)` | 从 `s` 向左在 `[max(0,s−w), s]` 内找最近 `spd<=move_exit` 样本；找不到 → 返回搜窗左端 `max(0,s−w)`，不报错。 |
| `snap_to_speed_min(spd, anchor, snap_window_s, fs)` | 在 `[anchor−w, anchor+w]` 内 `argmin`（NaN→inf）；空窗 → 返回 `anchor`。 |
| `clean_rest_gaps(env, inner_bursts, exit_e, min_rest_gap_s, fs)` | 相邻 inner burst 之间 `env<exit_e` 全程为真且长 `>=min_rest_gap_s·fs` 的间隙（用 `env<exit_e`，非补集）。 |
| `_env_argmin(env, gap)` | gap 区间内 `env` 最小值索引。 |
| `_rest_run_near(env, exit_e, idx, span, side)` | idx 前/后 `span` 样本内是否存在 `env<exit_e`（R7 用）。 |
| `resolve_move_thresholds(spd, env, exit_e, cfg)` | **实测新增**：`auto_move_thresh` 时 `(robust_threshold(spd, pose_pct, pose_mad), move_exit_frac·detect)`；否则/非有限 → `(cfg.move_enter, cfg.move_exit)`。 |
| `_motion_end_in(motion_runs, s, e, min_motion)` | 实测的 motion_end：首个 `me>s & ms<e` 的 settle 点，钳进 `[s+1, e-1]`；无则 `s+min_motion`（纯 hold 段名义短 motion）。 |
| `_valley_split(spd, ms, me, fs, move_enter)` | §7.2 saturated run 退路：`find_peaks(height=move_enter, prominence=0.5·move_enter)` 间谷底切。 |
| `_r7_splits(holds, bursts, env, exit_e, spd, cfg, fs)` | R7 背靠背否决（默认 OFF）。 |

**未落地的 helper（设计稿列出但代码无）**：`apex_index_guarded`（实测 apex 守护是 `segment_recording` 内联三层 fallback，不打 flag）、`last_hold_end`（末段直接 `end=n`）、`count_isometric`/`local_onset_lag`/`motion_run_covering`（R4-emg_only/R5/R6 未建）、`env_argmin`（实为 `_env_argmin`）。

### 10.6 核心检测器伪代码（已对齐 `action_segmentation.segment_recording` 实测）

> **此处的实测版本与设计稿差异：** ① `interpolate_short_nan_gaps` 不传 `min_finite_frac`；② 单位 rad/s；③ `resolve_move_thresholds` 派生 move 阈值；④ R7 由 `cfg.enable_r2`/`cfg.enable_r7` 门控；⑤ **无 R3 `both_quiet`、无 R5 qc 汇总、无 R6 `local_onset_lag`、无 `count_isometric`**；⑥ onset 不耦合 EMG-enter；⑦ apex 三层 fallback、review_flag 另行判定。返回 `(actions, dbg)`，`dbg` 带信号与计数器。

```python
def segment_recording(emg, ja, cfg):
    fs = cfg.fs
    ja = interpolate_short_nan_gaps(ja, fs, cfg.nan_max_gap_s)      # 无 min_finite_frac
    n = len(emg)
    spd = pose_speed(ja, fs, cfg.pose_smooth_ms)                   # rad/s 脊柱
    rest = np.nanmedian(ja, axis=0)                                # 仅 apex 排序
    bursts, env, enter, exit_e = segmentation.segment_emg(emg, cfg)         # Detector A
    move_enter, move_exit = resolve_move_thresholds(spd, env, exit_e, cfg)  # auto by default

    if not seg_range_ok(ja, 0, n, cfg.pose_min_range, cfg.min_finite_frac):  # R0+NaN guard
        return [], dict(pose_static=1)

    bursts, env, enter, exit_e = segment_emg(emg, cfg)             # Detector A
    motion_runs, holds = pose_hysteresis(                          # Detector B (新)
        spd, fs, cfg.move_enter, cfg.move_exit,
        cfg.min_static_s, cfg.min_motion_s, cfg.settle_frac)

    motion_runs, holds = pose_hysteresis(spd, fs, move_enter, move_exit,   # Detector B
                                         cfg.min_static_s, cfg.min_motion_s, cfg.settle_frac)

    onsets = []                                                    # R1 + R2
    for ms, me in motion_runs:
        if not seg_range_ok(ja, ms, me, cfg.pose_min_range, cfg.min_finite_frac):
            continue                                               # 噪声 bump / NaN 满布
        onsets.append(ms)                                          # 每个 run 都先记 onset
        if (me-ms)/fs <= cfg.pose_long_seg_s:  continue
        if not cfg.enable_r2:                  continue            # R2 可关
        inner = [(bs,be) for bs,be in bursts if ms <= (bs+be)//2 < me]
        gaps  = clean_rest_gaps(env, inner, exit_e, cfg.min_rest_gap_s, fs)
        if len(inner) >= 2 and gaps:
            for g in gaps:
                cut = snap_to_speed_min(spd, _env_argmin(env, g), cfg.snap_window_s, fs)
                if seg_range_ok(ja, cut, me, cfg.pose_min_range, cfg.min_finite_frac):
                    onsets.append(cut)
        else:                                                      # 无 rest 间隙 → §7.2
            onsets.extend(_valley_split(spd, ms, me, fs, move_enter))
    if not onsets:
        return [], dbg

    if cfg.enable_r7:                                              # R7 默认 OFF
        onsets += _r7_splits(holds, bursts, env, exit_e, spd, cfg, fs)

    onsets = sorted({snap_to_motion_foot(spd, o, fs, move_exit, cfg.snap_window_s)
                     for o in onsets})                             # snap + 去重 + 排序

    actions = []
    for i, s in enumerate(onsets):
        e  = onsets[i+1] if i+1 < len(onsets) else n               # 末段直接到 n
        me = _motion_end_in(motion_runs, s, e, min_motion)
        hs, he = me, e                                             # 真实 hold
        # apex 三层 fallback（无 flag 耦合）
        apex = (features.apex_index(ja, hs, he, rest, fs) if he-hs >= 2
                else features.apex_index(ja, s, he, rest, fs) if he-s >= 2
                else s)
        emg_in_motion = any(_overlap(bs, be, s, me) > 0 for bs, be in bursts)   # R4
        ftype = "both" if emg_in_motion else "pose_only"
        # review_flag 按优先级（非 apex 耦合）
        if   (me-s)/fs  > cfg.pose_long_seg_s: flag = "long"
        elif (he-hs)/fs < cfg.min_static_s:    flag = "nohold"
        elif not emg_in_motion:                flag = "slow"
        elif (he-hs)/fs > cfg.max_hold_s:      flag = "long_static"
        else:                                  flag = ""
        actions.append(dict(start=s, end=e, motion_start=s, motion_end=me,
                            hold_start=hs, hold_end=he, apex=apex,
                            fusion_type=ftype, review_flag=flag))
    return actions, dbg
    # 注：无 R3 both_quiet / R5 qc 汇总 / R6 onset_lag / count_isometric。
```

`pose_hysteresis` 实测要点：`settle = min(0.9·move_enter, max(move_exit, settle_frac·peak_run))`（上界钳 `0.9·move_enter`）；末尾 mid-motion 以 `len(spd)` 闭合最后一个 run。`_r7_splits` 仅在 `enable_r7=True` 时被调用。

---

**一句话总结（实测）：** pose-speed 双判据迟滞机当脊柱画 onset/边界（相对-settle 闭合修死区欠切、dip-merge 杀 velocity-peak 过切），EMG envelope 在 pose 合并出的超长 run（R2，默认开）补切；R7 背靠背否决**默认关**；绝对 `radians(15)` 位移 gate（带 NaN-fraction guard）兜 phantom，慢手势按 pose_only 保留。**检测算法本身未随数据层重构而变。** **数据层重构（重点）：** 权威索引是 `OUT/index.db`（`store.py`，clip `(source_file, clip_id)` 是打标/聚类/评估的统一键），顶层 `recordings.csv/bursts.csv/clips.csv` 是便利导出；schema 退役已发生（`static_in/out_*`、`clip_start/end`→`start/end`、`matched_emg_seg_idx`→`matched_burst_idx`、删 `gesture_label`、加 `seg_version`；全局 lag 三列**仍在**）；`segments.csv`→`bursts.csv`。两条聚类通道并列一等公民：`cluster.py`（APEX，聚 STATIC apex，经 `features.clip_features_for`）与 `cluster_traj.py`（轨迹/时序），都写 `cluster_runs/{run_id}/` + 注册 db；`evaluate.py` label-driven 按 run 评估；`export.py` 把人标 clip 导出到 `gestures/`；`label_server.py` 把标签/invalid/drop 写 `annotations`+`tombstones`。**实测反转/未建（检测层）：** move 阈值由 `robust_threshold` 逐录制自适应（非 EMG-rest 冷启动、非固定 60/25）、单位 rad/s；R3/R5/R6、`emg_label/calib.py` 均未落地。段 = 运动 + 真实 hold，右界落在下一 onset，无 pad、无 hold 上限。
