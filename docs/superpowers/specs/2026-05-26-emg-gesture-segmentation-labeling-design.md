## 0. 实测修订(基于真实数据,优先级高于下文原始设计)

原始设计基于单个样本文件。拿到真实数据(120 个 npz,均为 fgw-0917 左手,
分 8 个 run)后做了以下经实证的调整:

1. **切分信号:关节角度 → EMG 包络**。真实手势是“短暂动作+间歇放松”,关节角度
   距静息基线的信号在连续非中性手势间不回落,会把多个手势合并成一个超长段(实测
   最长 26s、约 5% 段受影响)。EMG 包络在每次肌肉放松时回到基线,能干净分隔。改用
   `emg_envelope`(mean|emg| 平滑)作为动作/静息信号(Otsu 阈值 + 迟滞 + 形态过滤),
   实测每文件稳定 ~30 段、无合并。聚类仍只用关节角度姿态。
   → `segmentation.segment_emg(emg, config)`。

2. **姿态特征:段中部 → 段末 → 保持顶点(apex-hold)**。EMG 段是动作爆发(手在移动);
   有区分度的“保持姿态”落在爆发**结束之后**的低肌电保持期(实测 ~67% 的手势其关节偏离
   静息的峰值在段末之后)。最终特征:在保持窗口 `[burst_start, next_burst_start)` 内取
   关节角度偏离静息**最大的那一帧(顶点)**附近的中位数姿态。
   → `features.apex_pose_feature(ja, start, window_end, rest, fs)`(2026-05-27 修订,
   取代早期的“段末 40%”`plateau_feature`)。聚类与 3D 姿态图都用此特征。

3. **聚类数 k 作为参数**。silhouette 自动选 k 倾向偏少(实测 17),会把姿态相近的
   不同手势合并(不可恢复)。因“过度聚类可用重复标签恢复、欠聚类不可恢复”,k 设为
   用户指定值更安全。`cluster.py` 新增 `--k N`(固定 k,覆盖范围搜索);保留
   `--k-min/--k-max` 自动搜索。当前采用 **k=18**(用户选定)。

4. **文件名解析:支持 run 后缀**。实际中段为 `{date}-{hand}[-{run}]`(如
   `20260502-left-3`)。`parse_file_info` 取第二个 token 为 hand,使同被试同手的
   不同 run 自动池化到一组 `fgw-0917-left`(经用户确认)。

5. **内存:逐文件处理**。`cluster.py`/`export.py` 按 source_file 分批加载、用完释放,
   避免 120 文件全缓存(~4GB)。

6. **模块拆分**:原计划的 `common.py` 实现为职责单一的多模块
   (`config/io_utils/segmentation/features/clustering/plotting`)。

下文 1–3、5–10 节的数据/分组/输出/测试约定仍然有效;第 4 节的切分与特征细节以本节为准。

## 1. 目标

从一批 npz 录制文件中,自动切分出"动作"片段(录制为"动作-静息-动作-静息…"交替),
通过聚类把片段分组,人工对每个聚类批量命名,最终把每个动作段导出为带标签的单独 npz,
并生成可视化图供人工核对。

手势集合是一套固定的约二十多个静态手势(数字手势 + 对指动作),录制时**顺序随机/未知**,
同一手势在一个文件内大概重复 2-3 次或更多。

## 2. 输入数据

- 输入:一个文件夹下的多个 `.npz` 文件。
- 每个 npz 含两个数组(已确认):
  - `emg`: shape `(N, 16)`,float32,sEMG,单位约为 µV(实测范围约 ±440)。
  - `joint_angles`: shape `(N, 20)`,float32,关节角度(数据手套),单位约为弧度(实测范围约 -0.74 ~ 1.63)。
- 两数组**逐样点同步**,采样率 `fs = 2000 Hz`(已确认)。
- 文件名约定:`{subject}__{date}-{hand}__{timestamp}.npz`
  - 例:`fgw-0917__20260502-left__20260502_115218.npz`
  - 解析:按 `__` 切三段 → `subject=第1段`;`第2段` 再按最后一个 `-` 切出 `hand`(如 `left`/`right`)。
  - **分组键 = (subject, hand)**。
  - 解析失败的文件:单独成组(组键 = 文件名),并打印告警,不中断。

## 3. 文件构成与聚类分组(已确认)

- 多被试、可能含左右手、**同一套手势集**。
- 因关节角度受手套标定/手大小/左右手镜像影响,**不能把所有文件混在一起聚类**。
- 策略:**同一 (subject, hand) 组的所有文件池化在一起聚类一次**;不同组分别聚类、分别命名。
- 手势名词表跨组共享(同一套手势),但每组的 cluster_id 各自独立,需分别命名。
- **明确不做(本期)**:跨组标签传播(用已标组的姿态模板给新组预填标签)。
- **明确不做(本期)**:EMG 参与切分判定(EMG 仅用于输出切片和可视化叠加)。

## 4. 处理流程(三阶段 + 一次人工)

### 阶段 1 · 切分 `segment.py`(逐文件)

对每个文件独立切分:

1. **静息基线姿态估计**(抗动作干扰的迭代法):
   - 取全局 `joint_angles` 逐通道中位数作为初始基线。
   - 计算各样点到基线的偏离;在偏离较小的样点子集上重算中位数,迭代 1-2 次得到稳健的静息基线。
2. **活动信号 `activity[t]`**:
   - 关节角度向量经低通平滑(默认 ~150 ms 窗口)后,到静息基线的欧氏距离。
3. **双阈值迟滞分割**:
   - `enter` 高阈值进入"动作",`exit` 低阈值退出"动作",避免边界抖动。
   - 阈值默认从 `activity` 分布自动确定(如基于中位数 + k·MAD,或 Otsu),可手动覆盖。
4. **形态过滤**:
   - 丢弃时长 < 最小动作时长(默认 0.4 s)的动作段。
   - 合并间隔 < 最小静息间隔(默认 0.2 s)的相邻动作段。
5. **输出**:
   - `segments.csv`:列 = `source_file, group, seg_idx, start_sample, end_sample, duration_s`。
   - 每个文件一张总览 PNG:在时间轴上叠加 EMG 包络、关节活动信号 `activity`、检测出的动作/静息区间,供人工核对切分是否正确。

### 阶段 2 · 聚类 `cluster.py`(逐组)

按 (subject, hand) 组池化所有动作段:

1. **姿态特征**:每段取**中部 50% 平台期**的 `joint_angles` 逐通道中位数(20 维),避免动作进出的过渡帧。
2. **归一化**:组内逐通道 z-score(均值/标准差在该组所有段上统计)。
3. **聚类**:在 k 范围内(默认 `12–30`,可固定单一 k 或改范围)用 KMeans;按**轮廓系数 (silhouette)** 选最优 k。
4. **输出**:
   - `labels_template.csv`:列 = `group, cluster_id, count, label`(label 列留空待填)。
   - 每组一张聚类预览 PNG:每个 cluster 画质心姿态(20 关节角度条形图)+ 实例数 + 几个代表段引用(source_file/seg_idx),供人工看图命名。

### 人工步骤

用户在 `labels_template.csv` 的 `label` 列填入手势名(每个 cluster 一行),另存为 `labels.csv`。

### 阶段 3 · 导出 `export.py`

读 `labels.csv` 与阶段 1/2 的中间产物:

1. 对每个动作段,从源 npz 切出 `emg`/`joint_angles` 片段。
2. 写为单独 npz,内容:
   - 数组:`emg`(切片)、`joint_angles`(切片)。
   - 元数据:`label, source_file, group, seg_idx, start_sample, end_sample, fs, cluster_id`。
3. 文件归档(按标签便于做训练集):
   - `out/segments/{label}/{label}__{subject}-{hand}__{source_stem}__seg{idx}.npz`
4. 每个文件一张**最终标注总览 PNG**:在信号上叠加各动作段及其标签。

## 5. 中间产物与目录约定

- 工作输出目录 `out/`(可配置):
  - `out/segments.csv`
  - `out/overview/{source_stem}.png`(阶段 1)
  - `out/labels_template.csv`、用户填好的 `out/labels.csv`
  - `out/clusters/{subject}-{hand}.png`(阶段 2 预览,每组一张)
  - `out/segments/{label}/*.npz`(阶段 3 导出)
  - `out/labeled_overview/{source_stem}.png`(阶段 3)
- 阶段间通过 CSV + 缓存(段边界、组划分)衔接,各阶段可独立重跑。

## 6. 可配置参数(均有默认值)

| 参数               | 默认       | 说明                 |
| ---------------- | -------- | ------------------ |
| `fs`             | 2000     | 采样率 (Hz)           |
| `smooth_ms`      | 150      | 活动信号低通平滑窗口         |
| `min_action_s`   | 0.4      | 最小动作时长             |
| `min_rest_gap_s` | 0.2      | 相邻动作合并的最小间隔        |
| `enter/exit 阈值`  | 自动       | 双阈值迟滞,默认自动,可手动覆盖   |
| ~~`plateau_frac`~~ | —      | 已删除(§0):特征改为 apex-hold 顶点中位数 `apex_pose_feature`,无此参数 |
| `k_range`        | (12, 30) | 聚类 k 搜索范围;也可指定固定 k |
| `out_dir`        | `out/`   | 输出目录               |

CLI:每个阶段一个脚本 + `argparse`;共享逻辑放 `common.py`(IO、文件名解析/分组、切分、特征、聚类、绘图)。

Python 3.13;numpy 2.4、scipy 1.17(滤波)、scikit-learn 1.8(KMeans + silhouette)、
matplotlib 3.10(绘图)、pandas 3.0(CSV)。均已安装确认。

## 8. 测试策略 (TDD)

用合成数据(不依赖真实 npz)对纯逻辑单元测试:

- **文件名解析/分组**:正常名、异常名(解析失败单独成组)。
- **切分**:构造合成"动作-静息-动作"关节角度信号(已知边界),验证检测出的段数与边界在容差内;验证最小时长过滤、相邻合并。
- **静息基线估计**:动作占比不同的合成信号下基线接近真实静息姿态。
- **特征提取**:平台中部中位数对过渡帧/噪声稳健。
- **k 选择**:构造 K 个明显簇的合成姿态,验证 silhouette 选出正确 k、分配正确。
- **导出命名**:标签/被试/手/段号正确拼接,目录归档正确。

绘图与真实 npz 端到端跑通做手动验证(不纳入自动化单测)。

## 9. 已知约束与风险

- 完全依赖关节角度切分;若某文件手套数据异常,切分会失效——总览 PNG 用于人工发现。
- 同组实例数仍可能偏少导致聚类边界不干净——预览 PNG + 可手动调 k 应对。
- 文件名不符合约定会退化为按文件分组(告警),不影响其余文件。
