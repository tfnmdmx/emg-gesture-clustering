# 字段说明（index.db / CSV 列 + 打标网页面板）

本文是数据各列的速查。权威列顺序定义在 [`emg_label/store.py`](../emg_label/store.py)
（`REC_COLS / CLIP_COLS / BURST_COLS / ANNOT_COLS`），数值在
[`segment.py`](../segment.py) 与
[`emg_label/action_segmentation.py`](../emg_label/action_segmentation.py) 计算。
`OUT/index.db` 是权威索引，`recordings.csv / clips.csv / bursts.csv` 只是它导出的
便捷副本（同名同义）。

## 0. 通用约定

- **采样率 `fs = 2000 Hz`**。所有 `*_sample` 是样本下标；换算秒 = `sample / fs`。
- **关节角加载后是弧度**（Manus 原始度数在 `io_utils.load_npz` 里转弧度）。所以
  `pose_range`、`pose_thresh` 等都是弧度 / 弧度每秒。
- **聚类 / 打标 / 评估的统一单元是 clip**：`(source_file, clip_id)`。
- 管线**两路检测**：姿态侧产出 **clip**（`clips` 表），EMG 侧产出 **burst**
  （`bursts` 表），再互相交叉匹配（`matched_*`）。

## 1. recordings 表（每条录制一行，录制级质检）

写入：[`segment.py:239`](../segment.py#L239)。

| 列 | 含义 |
|---|---|
| `source_file` | 录制标识名 `{stem}.npz`（合成名，作为本录制的主键） |
| `source_path` | npz 在磁盘上的**真实绝对路径** |
| `group` / `subject` / `hand` | 分组键 / 受试者 / 左右手 |
| `n_samples` | 总样本数；`duration_s = n_samples / fs` |
| `duration_s` | 录制时长（秒） |
| `n_bursts` | 检测到的 EMG burst 数 |
| `n_clips` | 检测到的姿态 clip 数（= 可打标段数） |
| `n_burst_only` | 没匹配到 clip 的 burst 数（有 EMG 无姿态） |
| `n_clip_only` | 没匹配到 burst 的 clip 数（有姿态无 EMG，偏复核） |
| `emg_pose_lag_s` | **EMG 包络 vs 关节速度的时间错位（秒）**。互相关求峰（[`qc.estimate_emg_pose_lag`](../emg_label/qc.py)）。正数=EMG 领先动作（生理正常 ~0–0.4s）；空=不可靠 |
| `emg_pose_corr` | 上面 lag 处的相关系数（越高越可信；<0.05 时 lag 记空） |
| `lag_flag` | lag 分类：`ok`(0–0.4s) / `early`(<0，EMG 晚于动作=同步错) / `late`(>0.4s，漂移/噪声) / `nan`(不可靠)。⚠️ **已知在本类准周期数据上有偏**（持姿期 EMG 才达峰，互相关易把绝大多数判成 `ok`），只作诊断参考、不门控任何下游步骤 |
| `pose_nan_frac` | **关节角缺帧比例**（任一关节非有限的帧占比）。高=Manus 遮挡/丢帧严重 |
| `emg_nan_frac` | **EMG 缺值比例**（非有限样本占比） |
| `enter_thresh` / `exit_thresh` | 自动推出的 **EMG 包络开 / 关阈值** |
| `pose_thresh` / `pose_exit_thresh` | 自动推出的 **姿态速度进入 / 退出阈值**（rad/s） |
| `rec_pose_range` | **整条录制的总活动幅度（弧度）**：全程每关节 `max−min` 再取 L2 范数。低=基本没动 |
| `pose_static` | **静止标记** 1/0：1=幅度太小/有限帧太少 → 判静止、不产生任何 clip |
| `seg_version` | **切分参数版本**（切分相关配置的 8 位 SHA1）。换参数后能识别旧标注是否过期并 remap |

## 2. clips 表（打标 / 聚类 / 评估单元）

写入：[`segment.py:205`](../segment.py#L205)。一条 clip = 一段无缝平铺的动作窗
（含 动 + hold + 到下一个起始的间隔）。

| 列 | 含义 |
|---|---|
| `source_file` | 所属录制 |
| `clip_id` | **本录制内 clip 的 0 起始时间序号**，即网页里的 `c####`。与 `source_file` 一起是下游主键 |
| `group` / `subject` / `hand` | 同录制 |
| `start_sample` / `end_sample` | clip 整段窗 `[start, end)` |
| `motion_start_sample` / `motion_end_sample` | 其中**真正在动**的子段（姿态速度超阈值） |
| `hold_start_sample` / `hold_end_sample` | 动作后的 **hold（定形保持）** 子段 = `[motion_end, end)` |
| `apex_sample` | **定形帧**：在 hold 窗内取“偏离静息中位姿势最大”的帧（[`action_segmentation.py:357`](../emg_label/action_segmentation.py#L357)）。这一帧的姿态向量就是 apex 聚类用的特征 |
| `duration_s` | clip 整段时长 `(end−start)/fs` |
| `motion_duration_s` | 运动段时长 |
| `hold_duration_s` | hold 段时长 |
| `emg_rms` | clip 窗内 EMG 的 RMS |
| `envelope_peak` | clip 窗内 **EMG 包络峰值**（肌肉激活强度，EMG 任意单位） |
| `mean_pose_speed` / `max_pose_speed` | clip 窗内姿态速度的均值 / 峰值（rad/s） |
| `pose_range` | clip 窗内每关节 `max−min` 的 L2 范数（**弧度**）= 这段手势的姿态变化幅度，越大动作越大 |
| `matched_burst_idx` | **匹配到的 EMG burst 序号**；`-1`=没匹配上 → 网页标“优先复核” |
| `fusion_type` | `both`=运动段内有 EMG burst 重叠（EMG 佐证） / `pose_only`=运动段内无 EMG |
| `review_flag` | 复核提示：`""`正常 / `long`一直没停的连续手势 / `nohold`动完没有真正 hold / `slow`轻柔手势、EMG 仅静息级（保留） / `long_static`hold/静止过长 |
| `seg_version` | 产生该行的切分参数版本 |

## 4. annotations 表（标注真值；clip_labels.csv / invalid_recordings.csv 已并入这里）

写入：[`label_server.py`](../label_server.py) 的 `set_label` / `set_recording_invalid`。

| 列 | 含义 |
|---|---|
| `source_file` / `clip_id` | 标注对象。`scope=recording` 时 `clip_id = -1` |

| `labeler` / `labeled_at` / `note` | 标注人 / 时间 / 备注 |

## 5. 打标网页面板对照

底部 clip 信息（[`webui/app.js`](../webui/app.js) `selectClip`，字段由
[`label_server.py:677`](../label_server.py#L677) 算出）：

```
s1 · c0000
dur 6.12s · motion 1.61s
env_peak 36.4 · pose_range 2.38
burst 0
```

| 显示 | 来源字段 | 说明 |
|---|---|---|
| `s1` | 网页临时排序位 | 本录制内按时间的第几个（**从 1**），纯人看的位置 |
| `c0000` | `clip_id` | 库里的正式 clip ID（**从 0**），见下节 |
| `dur 6.12s` | `duration_s` | clip 整段时长（含动+hold+间隔，故比 motion 长） |
| `motion 1.61s` | `motion_duration_s` | 真正在动的那段 |
| `env_peak 36.4` | `envelope_peak` | EMG 包络峰值 |
| `pose_range 2.38` | `pose_range` | 姿态变化幅度（弧度） |
| `burst 0` | `matched_burst_idx` | 匹配的 EMG burst 序号；`-1` 显示“优先复核” |

overview 上方的录制级行（`#ovinfo`，[`renderOvInfo`](../webui/app.js)）：

- 第 1 行：从 `processed_data` 起的原 npz 路径（悬停看完整绝对路径）。
- 第 2 行：本录制的**切分 QC / 阈值**，每段悬停有原列名+释义：
  `延迟 {emg_pose_lag_s}s（{lag_flag}）· 相关 {emg_pose_corr} · EMG阈值 进/出 {enter_thresh}/{exit_thresh} · 姿态阈值 进/出 {pose_thresh}/{pose_exit_thresh} · 切分版本 {seg_version}`

## 6. `c0000`（clip_id）vs `s1` —— 不是历史遗留

- `clip_id` 在 [`segment.py:157`](../segment.py#L157) 用 `enumerate(actions)` 生成，
  即**按时间顺序的 0 起始序号**。它是当前正式的 clip 标识，也是下游主键：标注、
  聚类、评估、导出、段位 chip 的 title 全用 `(source_file, clip_id)`。
- 标注入库时另带 `(clip_start_sample, clip_end_sample, seg_version)` 作为锚点，所以
  即便重切分，旧标注也能 remap，不靠 `clip_id` 本身稳定。
- `s1` 只是**每次打开网页时**按起始时间重排出来的 1 起始展示位置
  （[`label_server.py:691`](../label_server.py#L691)）。

所以二者分工：**`c0000` = 存库真实 ID（从 0）；`s1` = 给人看的“第几个”（从 1）**。
同一次切分里一一对应（`s = clip_id + 1`），看着像重复，但用途不同 ——
`c0000` 不是遗留字段。
